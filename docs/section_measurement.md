# 区間を測定し、走行ログから車体を調整する

最初は **「1回目のクランク」で、測定 → 調整 → 再測定**を1往復すると操作を覚えやすい。用意するものは、車体（RMC-RA4M1）、書き込み用USBケーブル、microSDとカードリーダー、Arduino IDE、Python 3.9以上、Brave。以下はWindowsでの手順。

## 1. PCで編集画面を開く

`mcr2026` フォルダーをPowerShellで開く。既存の作業用コピーを使う場合は、手元の設定変更を `git status --short` で確認してから、次を実行する。

```powershell
git switch main
git pull --ff-only origin main
py -3 tools/config_editor.py
```

`py` が使えない環境では `python tools/config_editor.py` でも起動できる。PowerShellに表示されたURL（通常は `http://127.0.0.1:8765/`）をBraveで開く。編集画面にローカルの設定が表示されたら準備完了。測定と調整の間は、このPowerShellを開いたままにする。

## 2. 測る区間を選び、車体に書き込む

1. **「走行調整」タブ**の「測定する区間」で「クランク」を選び、「何番目のクランク」に **1** を入力する。調整方法は「1走の記録・診断」を選ぶ。数字はスタートから車体が検出した**同じ種類の区間**を数える。右・左は合わせて数える。例えば「左クランク → レーンチェンジ → 右クランク」の右クランクを測るときは「クランク・2回目」。
2. **「停止・保存を設定」** を押す。これで選んだ区間の終了時に左右モーターの出力を0にする設定が編集画面に入る。クランクのブレーキを調整する場合は `USE_NEW_CRANK_BRAKE = 1` を確認する。区間選択ボタンで走行アルゴリズムのスイッチは切り替わらない。
3. 画面上部の **「保存」** を押し、表示された差分を確認して **「設定とスケッチを同期」** を押す。すでに同じ設定で「保存」が無効なら、そのまま次へ進む。編集画面は走行設定を `basic/config.h`、測定設定を `debug/dbg_config.h` に保存し、デバッグ用スケッチにも走行設定を反映する。
4. Arduino IDEで **`debug/debug.ino`** を開き、普段この車体に使っているボードとポートを選んで書き込む。IDEですでにスケッチを開いていた場合は、同期後の内容が読み込まれていることを確認する。**ブラウザで保存しただけでは車体の設定は変わらない。**

## 3. コースで1回走らせ、microSDからログを回収する

1. 電源を切った車体にmicroSDを入れる。車体をスタート位置に置き、スタートバーを閉じて電源を入れる。プッシュスイッチ待ちでバーを検出している間は、ボードのD13が点滅する。
2. **車体のプッシュスイッチを1回押し、スタートバーを開く。** バーが開くと走行と計時が始まる。狙った区間の入口と出口を目で追い、外にはらんだ、中央線を拾い直した、などの動きを控える。
3. 対象区間を抜けると車体がモーター出力を切り、通常ログを閉じてから専用CSVを保存する。**このモードでは終了時にスイッチを押す操作は不要。** 停止指令の後も惰性で進むので、車体の停止位置とプログラムが判定した区間の終端には差が出る。
4. **走行終了後、書き込み中のD13が点灯して消えたことを確認してから**電源を切り、microSDをPCで読む。通常ログと同じ番号の専用CSVを一緒にPCへコピーする。例えば最初のクランク走行が通番19なら `log0019.csv` と `CRK0019.csv`。**通番19は走行の番号**で、「19回目のクランク」という意味ではない。

| 測定する区間 | 車体が区間を抜けたと判定する目安 | 専用CSVの例 |
|---|---|---|
| クランク | クロスラインを検出してクランク処理に入り、曲がって通常トレースに戻る | `CRK0019.csv` |
| レーンチェンジ | ハーフラインを検出して車線変更処理に入り、新しい中央線のトレースに戻る | `LANE0019.csv` |
| カーブ | 大曲がり状態または推定舵角の絶対値5°以上が30 ms続いた後、トレース中に大曲がり状態を抜け、推定舵角の絶対値3°以下が70 ms続く | `CURV0019.csv` |
| 通常走行 | 直前のクランク・車線変更の出口から指定標識の通過確定まで。最初の標識ならスタートから | `TRCE0019.csv` |
| 総合 | スタートから指定標識の通過確定まで | `FULL0019.csv` |

通常走行と総合は、クロスラインと左右のハーフラインを合わせて数える。例えば「右クランク → 左レーンチェンジ」の2番目の標識を選ぶと、通常走行は右クランクを抜けてから左ハーフラインを通過するまで、総合はスタートから同じハーフラインを通過するまでを測る。最終クランクまで含めるには、その出口より先の標識を終点に選ぶ。

カーブの回数は車体の操舵で決まる。切り返しで直進が70 ms続かないS字では、見た目で二つのカーブでも一つとして記録されることがある。測りたい場所で終了したかを走行時に確認する。

## 4. 専用CSVを読み、次に試す値を決める

先ほどのBraveの画面で **「専用CSVで自動調整」** を押し、同じ走行番号の `CRK`・`LANE`・`CURV` のいずれかを開く。画面に判断に使った値と、設定の「現在値 → 候補値」が出る。速度と横加速度は車体モデルによる**推定値**。実際のはみ出しや中央線への復帰は目視結果と合わせて判断する。

| 区間 | 画面で比較するもの | 候補値の意味 |
|---|---|---|
| クランク | 曲がり角の線の通過時間や距離から補正した進入速度と計画速度 | 減速が遅ければ `CRANK_BRAKE_MARGIN_M` を増やす。増加は1回最大30 mm、減少は最大10 mm。画面に使えた実測と変更理由が出る。 |
| レーンチェンジ | 旋回開始時の推定速度・距離と計画 | `LANE_BRAKE_MARGIN_M` 等の候補を表示する。 |
| カーブ | 50 msでならした曲率から求めた横加速度の90パーセンタイルと設定上限 | 余裕が大きければ `CURVE_DRIVE_PERCENT` を上げ、上限超過時は下げる。1回最大5ポイント、上限100%。 |

**練習用CSV**　[CRK0001.csv](samples/CRK0001.csv) を「専用CSVで自動調整」で開く。初期値なら、計画1.00 m/sに対して進入1.20 m/s、減速距離が約41 mm不足し、余裕距離を0.05 mから0.08 mへ増やす候補が出る。このCSVは説明用に作ったデータで、8桁の `sensor` の各桁がセンサ1個に対応する。白線を検出するとその桁が1になる。実車の設定には、その車体で測ったログを使う。

## 5. 複数の設定をタイムで比較する

1. **「走行調整」タブ**で区間の種類と何番目かを指定し、調整方法の **「タイム比較（設定ごとに3走）」** を選ぶ。続いて**「タイム比較を開始」→「保存」→「設定とスケッチを同期」**。Arduino IDEで **`debug/debug.ino`** を書き込む。試験ごとの識別番号もこのとき車体に入る。
2. 同じコース・スタート位置・DIP・電池条件で3走する。走行ごとに電源を入れ直し、SDの通番を維持する。毎回同じ位置で停止指令が出たことを目で確認する。**「比較用CSVを追加」** からその3走の専用CSVを選ぶ。1走ずつでもよい。
3. 基準3走が完了すると中央値と最初の候補（例 `CRANK_BRAKE_MARGIN_M 0.05 → 0.045`）が出る。再び **保存・同期 → debugを書き込み → 同条件で3走 → CSVを追加**。同じ走行や古い設定のCSVは重複計上しない。途中停止した走行も読み込ませる。
4. 3走がすべて同じ標識列で完了し、中央値の短縮が2 msと両設定の中央値絶対偏差をどちらも超えたときに採用する。途中停止・標識列の違い・改善不足なら元の採用値に戻して次の候補を表示する。カーブとクランクの区間タイムには操舵開始・復帰位置の変化も含まれる。採用した設定は、同じ物理標識を終点にした「総合」でも確認する。
5. 途中で切り上げるときも **「比較を終了・採用値に戻す」→ 保存・同期**。未評価の候補が外れる。通常の走行には **`basic/basic.ino`** を書き込む。続きから試すときは同じブラウザ・URLで同じフォルダを開き「タイム比較を開始」を押す。

### どの値を試すか

| 測る場所 | 比較に含む主な走行設定 |
|---|---|
| クランク・車線変更 | 進入速度、ブレーキ出力と余裕距離、旋回・復帰の条件、グリップ使用率。旧方式の段階・時間・出力表も対象。 |
| 通常走行・カーブ | 駆動倍率、速度段階の切替時間、速度計画・線追従の係数、ログに現れたセンサ値・段階に対応する操舵角と左右モーター出力。 |
| 総合 | 各区間の候補と共通設定を、スタートから指定標識までのタイムで評価する。 |

1候補ずつ、設定の上下を小さく変えて試す。制御方式を切り替える候補では、ビルドに必要な従属スイッチも一緒に変わる。表の候補は `basic/tables.h` に保存され、同期時に `debug/tables.h` に反映される。ホイールベース、実測グリップ、コースの線幅、サーボの物理限界などは採寸・校正した値を使う。全組み合わせの最速を保証する探索ではない。

## 6. 調整前後を比べ、通常走行に戻す

- スタート位置、対象区間と回数、DIPスイッチ、できるだけ電池条件を揃える。比較中は他の走行パラメータを固定する。
- 走行ごとに **ログ番号／変更した値／画面の推定値と目標値／実際に見た動き** を記録する。クランクなら、進入速度が計画に近づいたか、出口で安定して中央線に復帰したかを前走と比べる。ある区間用に保存した走行設定は、同じ制御を使う他の区間にも効く。
- 結果が悪化した場合は、控えた元の値を編集画面に入力し、保存・同期して書き込み直す。候補値を採用するたびに、その値で新しく取ったCSVを次の比較に使う。
- 調整後は **`basic/basic.ino` を書き込み、コース全体を通して確認する。** 保存済みの走行設定を使って、区間デバッグの自動停止を外した状態で走れる。通常の走行時間制限 `AUTO_STOP_MS` は引き続き有効。

## うまく測れないとき

| 状況 | 確認と次の操作 |
|---|---|
| 目的の区間より前で止まる | スタート位置と回数、実際に検出した区間、コースアウトの有無を確認する。時間制限 `AUTO_STOP_MS` はこの版で30,000 ms。対象がそれより後なら必要な走行時間に合わせて変更し、同期・再書き込みする。 |
| 通常ログしかない、または `DBG` しかない | `debug/debug.ino` を書き込んだか、`DBG_ENABLE = 1`、`DBG_AUTO_STOP = 1` かを確認する。書き込みエラーはシリアルモニタ（9600 bps）で確認できる。SDに同じ番号の専用ファイルがある場合は上書きしないので、既存ログを退避してから再測定する。 |
| 「対象区間の完走と書き出し完了を確認できません」 | 同じ番号の専用CSVを選んだかを確認する。途中停止は先頭付近の `#reason,2`、区間完了は `#reason,1`。末尾の `#complete` がない場合は書き出し完了を確認できない。元のCSVを加工せず、区間完了・D13消灯まで待って取り直す。 |
| 「区間全体が必要です」 | 記録できる時間は「記録間隔 × 件数」が目安。標準450件で区間設定後はクランク・車線変更が約2.25秒、カーブが約4.5秒。区間が長い場合は「停止・保存を設定」を押した**後**に `DBG_INTERVAL_MS` を長くするか、RAMに余裕があれば `DBG_SAMPLES` を増やし、同期・再書き込みする。 |
| 「計算による減速が無効」「区間内の速度推定を使用できません」 | 前者は対象の減速スイッチを確認し、有効にして新しく測る。後者はCSVの `model_ok`、車体・コースの設定、ライン検出を確認して再測定する。 |
| 「走行時の設定と一致しません」／編集中に外部変更が出た | 前者は現在の設定を書き込んでもう一度測る。後者は必要な編集値を控えてから「ディスクから再読込」で最新のファイルを読み、必要な変更を入れ直す。 |

車体寸法・グリップなどの測り方は[実機での調整手順](tuning_guide.md)、CSVの各列と詳しい解析方法は[デバッグモードの説明](../debug/README.md)を参照。
