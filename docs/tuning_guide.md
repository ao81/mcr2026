# 実機での調整手順

Web編集画面で区間を選び、車体を止めて専用CSVから調整する操作は、[区間を測定し、走行ログから車体を調整する](section_measurement.md)を参照してください。

このファイルは、実機がないとできない確認と数値の調整を、作業する順番に書いたものです。
数値はすべて `basic/config.h`（時間・速度・新しいアルゴリズムの設定）と `basic/tables.h`（センサ値ごとの表）にあります。

## 0. 今のプログラムの状態

| 項目 | 状態 |
|---|---|
| リファクタリング | 走行の動きは元のプログラムと同じ。PC 上で 23000通りの入力を与え、1ms ごとの出力がすべて一致することを確認済み |
| 新しいアルゴリズム | `config.h` の15個のスイッチ `USE_NEW_*` で1つずつ切り替える。初期値は、クランク関係（`CRANK_BRAKE`・`CRANK_TURN`・`CRANK_QUICK`・`BRAKE_RANGE`）と `VMAX_LEARN`、レーンチェンジ関係（`LANE_BRAKE`・`LANE_STEER`・`LANE_DISTANCE`、2026-11-24 から）が `1`、ほかは `0`（元の動き）。今回追加した車線変更用の3個はPC版で検証。以前の12個の版では全オフの動作をPC上で3000通りの入力で比較し、RA4M1向けのビルドも確認済み |
| PC での模擬 | `tools/course_sim/` でクランク・レーンチェンジ・180° カーブ・S字を模擬し、計算どおりに曲がることと、車の値がずれた場合にどこまで走れるかを確認済み（結果は 8 章） |
| 実機での確認 | まだしていない |

> **走行時間**　`basic/config.h` の `AUTO_STOP_MS` がスタートからの制限時間です。1周を測るときは予定の周回時間より長く設定してください。
>
> **ログを閉じる操作**　通常走行で時間制限・コースアウトにより止まったとき（pattern 800, 801）は、停止後に**プッシュスイッチを押して**ログを閉じてください。区間デバッグで `DBG_AUTO_STOP = 1` のときは自動で閉じます。専用CSVの書き込みを示すD13が点灯して消えるまで待ってください。

## 1. まず、リファクタリング後のプログラムが前と同じに走るか確かめる

1. Arduino IDE で `basic` フォルダの `basic.ino` を開きます。上のタブに `config.h`、`tables.h`、`hardware.ino`、`planner.ino` などが並んでいれば正しく開けています。
2. `config.h` の `USE_NEW_` で始まる15個が、すべて `0` になっていることを確認します。
3. いつもと同じ手順で書き込みます。`mcr_gpt_lib.h` は今まで通りライブラリとして入っている必要があります。
4. 前のプログラムで走らせたことのあるコースを、DIPスイッチも同じ設定にして3回走らせます。
5. microSD のログ（`logNNNN.csv`）を前のプログラムのログと比べます。列の並びは前と同じです（`ms,pattern,sensor,handle,motor_l,motor_r`）。
   - 同じ場所で同じ pattern 番号に変わっていれば問題ありません。
   - 走るたびに細かい違いは出ます（センサの読み取りやバッテリーの電圧が毎回少し違うため）。

ここで動きが明らかに違う場合は、新しいアルゴリズムに進まずに連絡してください。

## 2. 新しいアルゴリズムの考え方

新しいアルゴリズムは、どれも「タイヤのグリップ（すべらずに出せる加速度）とコースの幅の範囲で、一番速くなる走り方」を計算で求めます。
表の数値を走って合わせるのではなく、測れる値（車体の寸法、グリップ、最高速度など）から決まるので、車やコースが変わっても計算し直すだけで済みます。

| スイッチ | 変わる所 | 使う計算 |
|---|---|---|
| `USE_NEW_CRANK_BRAKE` | クロスラインからクランクまでの減速 | 全開 → ぎりぎりで最大ブレーキ → 目標の速さを保つ（2-2） |
| `USE_NEW_CRANK_TURN` | クランクの曲がり方 | コースからはみ出さない一番大きい半径の円弧1つ（2-3） |
| `USE_NEW_LANE_BRAKE` | ハーフラインから中央線の切れ目までの減速 | クランクと同じ（2-2） |
| `USE_NEW_LANE_STEER` | 車線変更の曲がり方 | 同じ半径の円弧2つをつないだS字。半径が一番大きくなる長さ（2-4） |
| `USE_NEW_TRACE_SPEED` | 通常走行（pattern 20〜25）の速さ | ハンドル角度で決まる半径を、横すべりしない一番速い速さで回る（2-5） |
| `USE_NEW_CURVE_SPEED` | 大曲がり（pattern 30〜45）の速さ | 同上 |
| `USE_NEW_STEER` | 通常走行のハンドル角度 | ピュアパシュート（線の位置から曲がる半径を計算する）（2-5） |
| `USE_NEW_TRACTION` | 加速するときのモータ出力 | 摩擦円で残っている分までしか加速しない（2-5） |
| `USE_NEW_VMAX_LEARN` | 速さの推定 | ラインを通るたびに、出力100%の速さを測り直す。どれだけ直すかはカルマンフィルタで決める（2-1） |
| `USE_NEW_LINE_SHAPE` | 通常走行・大曲がりのハンドル角度 | 線の位置・向き・曲がり具合を推定し（オブザーバ）、サーボが遅れる分だけ先の位置でハンドルを切る（2-9） |
| `USE_NEW_CURVE_PREVIEW` | 通常走行・大曲がりの速さ | 推定した「センサの所の曲がり具合」で後輪がカーブに入る前から減速し、出口はサーボの本当の角度に合わせて加速する（2-10） |
| `USE_NEW_CRANK_QUICK` | クランクの曲がり方 | 手前で必要なだけ減速し、ハンドルを大きく切った小さい半径で 90°曲がり、90°に着く前にハンドルを戻し始める（2-14） |
| `USE_NEW_BRAKE_RANGE` | クランク・レーンチェンジ手前の減速 | ラインを見つけた瞬間から、本当に曲がり始める所までの距離を全部使って減速する（2-11） |
| `USE_NEW_LANE_WIDTH_INTERVAL` | ハーフラインを抜けたときの速度推定（改善案A） | 推定速度が1 msの通過時間誤差と両立するときは、その回の補正を見送る |
| `USE_NEW_LANE_DISTANCE` | 中央線の切れ目での速度推定（改善案B） | `USE_NEW_LANE_STEER=1` で、S字に入る前に積算距離と `HALF_TO_LANE_M` を照合する |
| `USE_NEW_LANE_DOWN_ONLY` | 改善案Bの補正方向 | 距離補正が有効なとき、0で上下両方向、1で下方限定 |

[検証レポート](algorithm-optimality.md)の比較を再現するときは、以前からある12個のスイッチを1にしてから上記3個を切り替える。最高速の推定値も補正するのは `USE_NEW_VMAX_LEARN=1` の場合。車体の設定にはハーフラインの末端から中央線の切れ目までの距離を入れる。

組み合わせの決まり（守らないとビルドのときにエラーになります）：

- `USE_NEW_LANE_BRAKE` は `USE_NEW_LANE_STEER` と一緒に 1 にします。元の車線変更は、元の減速のあとの速さに合わせた時間でハンドルを切ります。減速だけ新しくすると時間が合わず、模擬ではどの速さでもコースアウトしました。
- `USE_NEW_LINE_SHAPE` は `USE_NEW_STEER` と、`USE_NEW_CURVE_PREVIEW` は `USE_NEW_TRACE_SPEED` と一緒に 1 にします。どちらも、もう一方の計算を置き換えるものなので、単独では働きません。
- `USE_NEW_BRAKE_RANGE` は、`USE_NEW_CRANK_BRAKE` / `USE_NEW_LANE_BRAKE` を 1 にしている方だけが変わります。
- `USE_NEW_CRANK_QUICK` は `USE_NEW_CRANK_TURN`・`USE_NEW_CRANK_BRAKE` と一緒に 1 にします（`USE_NEW_BRAKE_RANGE` も 1 にすると速くなります）。
- `USE_NEW_CRANK_BRAKE` だけを 1 にする（`USE_NEW_CRANK_TURN` は 0）ときは、`CRANK_ENTRY_MPS` に元の曲がり方でうまく曲がれる速さを入れます（模擬では 1.4 前後）。自動の計算（0）は円弧で曲がる場合の値なので、元の曲がり方には合いません。

### 2-1. 速さの求め方（すべての新しいアルゴリズムで使う）

Basicマイコンカーには、速さを直接測るセンサ（エンコーダ）がありません。そこで次の方法で速さを求めています（`speed_model.ino`）。

1. **モータの出力から計算する**：出力 p[%] を出し続けると、速さは `p/100 × V_MAX_MPS` に近づいていきます。近づく速さは時定数 `MOTOR_TAU_S` で決まります（一次遅れのモデル）。これを 1ms ごとに計算し、速さを足して距離も求めます。加速はタイヤのグリップ `GRIP_LONG_MPS2` より速くならないとし、曲がっている間は摩擦円（2-6）で残っている分までにします。
2. **ラインの通過時間で測り直す**：クロスラインとハーフラインは幅が決まっています。通過にかかった時間から `速さ = 幅 ÷ 時間` で実際の速さが分かります。
   - 時間は「数えた ms ＋ `LINE_PASS_OFFSET_MS`（1ms）」です。センサは 1ms ごとに見るので、ラインに乗ってから見つけるまで平均 0.5ms 遅れ、さらに見つけた次の割り込みから数え始めるので、始まりで 1.5ms 足りません。終わりはラインを出てから気づくまで平均 0.5ms 多く数えます。差し引きで 1ms 足します（前の版は 2ms 足していたため、測った速さが 5〜8% 遅く出ていました）。
   - 1 の計算値と測った値の両方に誤差があるので、2つを誤差の大きさに応じて混ぜます（カルマンフィルタ。2つの誤差の2乗の和が最も小さくなる混ぜ方）。混ぜる割合は `K = P ÷ (P + R)` です。P は計算値の誤差の大きさ（`USE_NEW_VMAX_LEARN` が 0 のときは 0.1²。1 のときは 3 の方法で求める）、R は測定の誤差の大きさ（1ms 単位で数えることによる `(0.41ms ÷ 通過時間)²` と、ラインの見える幅の誤差 `LINE_WIDTH_SD`² = 0.03²）です。初期値では、初めの1回の K は 0.85 ほどになります。
   - 測った値が計算値の 0.6 倍より小さいか 1.67 倍より大きいときは、測り間違い（斜めに横切った、線を見落としたなど）か `config.h` の値の大きな間違いです。どちらか分からないので、速い方の値を使います（ブレーキが遅れない側）。2回続いたら速さの推定を使うのをやめ、元の表の動きに戻ります（2-7）。
3. **出力100%の速さを走りながら求める（`USE_NEW_VMAX_LEARN`）**：最高速度は電池や車体でその時ごとに変わるので、`V_MAX_MPS` は「最初の見当」としてだけ使い、走りながら測った速さで出力100%の速さ（`v_max_mps`）を求めます（2026-11-25 から。それまでは `V_MAX_MPS` の ±25% の範囲でしか直さなかった）。
   - 計算した速さが `v_max_mps` にどれだけ左右されているか（感度 s）を 1ms ごとに計算しておきます。出力 p% を出している間は s が p/100 に向かって時定数 `MOTOR_TAU_S` で近づき、グリップで頭打ちの加速・ブレーキの間は変わりません。スタートから全開なら s ≒ 1、ブレーキの後に p% で一定の速さを保っていれば s ≒ p/100 です。
   - 速さを測ったら、「測った速さ − 計算した速さ」を、`v_max_mps` の誤差（s 倍で効く）とそれ以外の誤差（グリップの誤差 `SPEED_GRIP_ERR` から積もる分）に、誤差の大きさに応じて分けて、速さと `v_max_mps` の両方を直します（2つの値のカルマンフィルタ）。初めの `v_max_mps` の誤差は `VMAX_LEARN_SD`（50%）、走っている間に 1 秒あたり `VMAX_DRIFT_SD`（2%）ずつ変わり得るとします（電池の電圧が下がる分）。
   - 速さを測る所：幅が1つに決まっているクロスライン・ハーフライン、クランクの曲がり角の線（中央線。規則で幅 20mm）。`USE_NEW_CRANK_ANY_COURSE` でクロスラインの幅が分からないときも、あり得る幅（`COURSE_LIST` の候補、無ければ規則の 20〜40mm）の真ん中の幅で速さを出し、幅の範囲の分だけ誤差が大きい測定として使います。
   - 測った値が計算値の 0.6 倍より小さいか 1.67 倍より大きくても、`v_max_mps` の誤差で説明できる大きさ（3σ 以内）なら測り間違いとはみなしません。
   - 模擬（2つ続くクランク `crank2`、外側・内側スタート、本当の値 1.7 と 2.5 m/s、`V_MAX_MPS` 1.0〜3.0、各7回）：直す前は `V_MAX_MPS` が本当の値と 1.3 倍ほどずれると7回とも失敗していました。直した後は、`V_MAX_MPS` が本当の値の 0.48〜1.76 倍の範囲で失敗は 182 回中 2 回、時間は `V_MAX_MPS` によらずほぼ同じ（差 2〜4%）です。`V_MAX_MPS` が本当の値の 0.4 倍（1.0 と 2.5）だと外側スタートで7回とも失敗するので、見当は半分より大きくしてください。

通過時間は 1ms 単位で数えるので、3m/s で 40mm の線を通ると 13ms か 14ms のどちらかになります。速さにすると 7〜8% の差です。この誤差は避けられないので、計算には余裕を持たせています（2-6）。

### 2-2. クランク・レーンチェンジ手前の減速（`USE_NEW_CRANK_BRAKE` / `USE_NEW_LANE_BRAKE`）

- **元の方法**：クロスラインの通過時間ごとに「全開の時間」「ブレーキの強さ」を決めた表（25段階）を使っていました。
- **新しい方法**：ラインを通過し終わった地点からの距離を計算し続けます。1ms ごとに「次の1msも全開で進んだ後にブレーキをかけたら、目標の速さまで落ちるのに何 m 必要か」を計算します。その距離が残りの距離（`CROSS_TO_CRANK_M − 走った距離 − CRANK_BRAKE_MARGIN_M`）より短いうちは全開で走ります。足りなくなった瞬間にブレーキをかけ、目標の速さまで落ちたら、その速さを保ちます。
- **ブレーキで進む距離の計算**：速いうちはグリップで決まる一定の減速度 G で落ちるので `(v² − v₁²) ÷ 2G`、遅くなってモータの力の方が小さくなってからは指数関数で落ちる分を足します（`braking_distance`）。
- **目標の速さ**：`CRANK_ENTRY_MPS` / `LANE_ENTRY_MPS` が 0 なら、曲がる円弧の半径から自動で決めます（2-3、2-4）。
- **この方法を選んだ理由**：加速と減速の強さに上限がある場合、決まった距離で目標の速さまで落とすのに一番時間がかからないのは、「全開 → ぎりぎりで最大ブレーキ → 目標の速さを保つ」という切り替え方です（最適制御でバン・バン制御と呼ばれる方法）。表で決める方法と違って、速さやラインからの距離が変わっても、ブレーキを始める地点が自動でずれます。
- **目標の速さに近づけるとき**：「次の1msでちょうど目標の速さになる出力」を計算して出します（デッドビート制御）。出力の上限・下限で頭打ちになるので、目標から遠いときは全開かブレーキ、近づくと保つ出力に自動で変わります。

### 2-3. クランクの曲がり方（`USE_NEW_CRANK_TURN`）

- **元の方法**：曲がり角の線を見つけたらハンドルを最大近くまで切り、表の時間だけ待ってから線を探していました。
- **新しい方法**：90° を1つの円弧で曲がります。横すべりせずに曲がれる速さは `v = √(グリップ × 半径)` なので、半径が大きいほど速く曲がれます。そこで、コースからはみ出さない一番大きい半径を計算します（`planner.ino` の `crank_plan`）。
  - 外側：外側の前の角が、新しい道の向こう側の端を越えない → 半径の上限
  - 内側：内側の後輪が、内側の角を切り込まない → 半径の下限
  - 上限が下限以上なら曲がれます。半径は上限（一番大きい値）にします。今すぐ曲がると内側の角に当たる場合は、上限と下限がちょうど等しくなる所まで直進してから曲がります。
- **サーボの遅れ**：指令を出してからサーボが角度に着くまでの間は直進しているとみなします。遅れは `SERVO_DEAD_S + 角度 ÷ (2 × SERVO_SPEED_DPS)` で、その間に進む分だけ曲がり始めの位置を奥にずらして計算します。
- **走り方**（pattern 112 / 152）：
  1. 計算した距離だけ直進します（ほとんどの場合 0）。
  2. 計算した角度（小数のまま）で、円弧 90° 分の距離を走ります。円弧の `CRANK_ARC_EXIT_RATIO`（70%）以上を走った後に新しい線が中央に見えたら、その時点で通常走行へ移ります。
  3. 90° 分の指令を出し終えたらハンドルを戻し、線が見えたら通常走行へ。サーボが戻る時間を過ぎても見えなければ、元の復帰処理（120 / 160）へ移ります。
  4. 途中で外側の白線が見えたら（はみ出した）、元の処理（121 / 161）へ移ります。
- **入る速さ**：`CRANK_ENTRY_MPS` が 0 なら、`速さ → 曲がり始めの位置（v × 遅れ）→ 半径 → その半径で曲がれる速さ → …` を8回くり返して決めます（速いほど曲がり始めが遅れて、半径が小さくなるため）。

### 2-4. レーンチェンジの曲がり方（`USE_NEW_LANE_STEER`）

- **元の方法**：中央線が切れたら決まった角度でハンドルを切り、表の時間だけ保ってから戻していました。
- **新しい方法**：同じ半径 R の円弧2つ（変える側へ曲がる → 逆へ曲がる）をつないだS字で、横に `LANE_SHIFT_M` だけずれます。前に L 進む間に横に d ずれるとき、半径は `R = (L² + d²) ÷ 4d` です。L が長いほど R が大きく、速く走れます。そこで、次の2つを満たす一番長い L を二分法で求めます。
  1. 古い車線：中央線が切れる所より手前にいる間、変える側の車体の角が古い車線の端を越えない
  2. 新しい車線：区間の終わり（中央線が切れてから `LANE_SECTION_M` 先）を越えるとき、反対側の車体の角が新しい車線の中に入っている
  - 1 が満たせないときは、1cm ずつ直進する距離を増やして探します（8cm まで）。
  - この形を選んだ理由：決まった距離で横に決まった分だけずれる経路のうち、一番きつい所の半径が最大になるのが、同じ半径の円弧2つの形です。
- **線の位置の補正**：中央線が切れる直前の、線に対する車の横の位置を覚えておき、その分を引いて横に動く距離を計算します。
- **サーボの遅れ**：逆向きに切り返すときは、サーボが動いている途中の真ん中で向きが変わったとみなせます。その分だけ早く切り返すと、1つ目と2つ目の円弧の長さがそろいます。
- **走り方**：S字（pattern 360〜370 / 660〜670）の間はセンサを見ません。走り終えたら（380〜390 / 680〜690）新しい線を探します。
  - 通常走行の表にある形で線が見えた → 通常走行へ
  - 変える側の端にだけ見えた（横に動き足りない）→ 元の処理（400 / 700）へ
  - それ以外の形で見えた（速さの推定の誤差で行き過ぎた場合など）→ 線の方へ、横すべりしない角度までハンドルを切る
  - `LANE_SEARCH_M` 走っても見えない → 変える側へ `LANE_STRAIGHT_ANGLE` だけハンドルを切る
- **距離の誤差への備え（`LANE_DIST_ERR`、初期値 0.03）**：S字の間は、推定した速さから求めた距離だけで走ります。速さを 5% 速く見ていると、どちらの円弧も 5% 短く走り、横に動く量はおよそ 10% 足りなくなります。そこで、2 の条件を「走った距離が `LANE_DIST_ERR` の割合だけ短かった場合（円弧1つで回る角度が φ(1 − e) になる場合）」にも満たす L を選びます。0 にすると区間をぎりぎりまで使う最も緩い経路になり、模擬では 1回のレーンチェンジが 20ms ほど速くなります。ただし、ラインで測る速さが 1ms の数え方の誤差で 5% ずれただけで外に出ることがありました（8 章）。
- **計算時間**：経路は、中央線が切れる直前の車の横の位置（−40〜+40mm、5mm おき）の17通りについて、setup で計算して表にしておきます（`lane_table_setup`）。走行中は表を引くだけなので、1ms の割り込みの中で時間がかかりません。経路は「一番速く受け付ける速さ」（曲がれる速さ × `PLAN_OVERSPEED`）で計算し、線を見つけてから曲がり始めるまでの距離 u を覚えておきます。実際の速さ v がそれより遅いときは、待つ距離を `u − v × 遅れ` にすると、同じ位置から同じ経路を走れます。表の範囲の外のときだけ、走行中に計算します（一番遅い場合 3ms ほどで、その時だけ次の割り込みが 2〜3回遅れます）。

### 2-5. 通常走行（`USE_NEW_TRACE_SPEED` / `USE_NEW_CURVE_SPEED` / `USE_NEW_STEER` / `USE_NEW_TRACTION`）

- **速さ（`USE_NEW_TRACE_SPEED`、大曲がりは `USE_NEW_CURVE_SPEED`）**：ハンドル角度 θ から曲がる半径 `R = WHEELBASE_M ÷ tan θ` を求め、横すべりしない一番速い速さ `v = √(グリップ × R)` で走ります。
  - 左右の後輪は、内側と外側で回る距離が違います。外輪 = 中心の速さ × (1 + 曲率 × `TREAD_M`/2)、内輪 = 中心の速さ × (1 − 曲率 × `TREAD_M`/2) にします。外輪が 100% を超えるときは、比を保ったまま両方を下げます。
  - センサは 10mm おきなので、カーブの途中でもハンドル角度は2つの値を行き来します。速さは、曲率を `TRACE_CURV_FILTER_S`（30ms）の時定数でならした値で決めます。
  - 曲がれる速さより速いときは、`TRACE_MIN_POWER`（−60%）までブレーキをかけます。
- **ハンドル角度（`USE_NEW_STEER`）**：ピュアパシュートという方法です。センサで見た線の上の点（前に Ld、横に e）を通り、今の向きに接する円の曲率 `κ = 2e ÷ (Ld² + e²)` で曲がります。Ld は、一番外側のセンサで線を見たときに、ちょうどコースの最小半径 `TRACE_MIN_RADIUS_M`（450mm）で曲がる長さにしています。線がセンサの中にあるうちに、一番急なカーブを曲がれる角度が出ます。
- **加速の制限（`USE_NEW_TRACTION`）**：加速の出力を、摩擦円で残っている分までにします。タイヤが空回りすると前に進む力が下がるのを防ぐためです。ブレーキは制限しません。
- **模擬での結果**：8 章にあります。通常走行は、元の表が実機で調整されているので、新しい方法の方が速いとは限りません。最後に試してください。
- このほかに、カーブでの判断を良くする2つのスイッチ（`USE_NEW_LINE_SHAPE`、`USE_NEW_CURVE_PREVIEW`）があります（2-9、2-10）。

### 2-6. 余裕の持たせ方

計算どおりの「理論上の限界」で走ると、測った値が少しずれただけで失敗します。模擬では、余裕をすべてなくすと、車の値が設定と同じでもクランクを7回中5回失敗しました（ラインの通過時間の誤差だけで）。そこで、次の余裕を初期値に入れています。

| 設定 | 初期値 | 内容 | 理論上の限界 |
|---|---|---|---|
| `PLAN_GRIP_RATIO_LAT` | `0.90` | 曲がる速さの計算に使う横のグリップの割合。0.9 で曲がる速さは約 5% 下がる | 1.0 |
| `PLAN_GRIP_RATIO_LONG` | `0.90` | ブレーキの計算に使う前後のグリップの割合。ブレーキを早めに始め、速さの推定は遅めに減速すると考える | 1.0 |
| `COURSE_MARGIN_M` | `0.020` | クランク・レーンチェンジの経路で、コースの端から残す距離 [m] | 0 |
| `CRANK_BRAKE_MARGIN_M` / `LANE_BRAKE_MARGIN_M` | `0.05` | ブレーキを早めにかける距離 [m]。距離の推定の誤差（1m で ±5%）の分 | 0 |
| `PLAN_OVERSPEED` | `1.05` | 曲がり始めの速さが計画の 1.05 倍を超えたら、計画をやめて元の方法で曲がる | ― |
| `LANE_DIST_ERR` | `0.03` | レーンチェンジのS字を、走った距離が 3% 短くても新しい車線に入る経路にする（2-4） | 0 |
| `TRACE_SAFE_RADIUS_M` | `0`（使わない） | 直線の速さを、この半径のカーブが急に来ても曲がれる速さまでに抑える（2-10） | ― |

グリップの値の使い分け：加速の計算には測った値そのまま、ブレーキと曲がる速さの計算には割合をかけた値を使います。どちらも「推定した速さが実際より速め」になる側で、ブレーキが遅れないようにするためです。

本当の値が設定からずれた場合の模擬の結果は 8 章にあります。

### 2-7. 元の方法に戻る条件

新しい方法で曲がれないと分かったときは、元のプログラムの方法で曲がります。

| 場面 | 元の方法に戻る条件 |
|---|---|
| クランク | 計算した円弧が、ハンドルを `SERVO_MAX_ANGLE` まで切っても曲がれない半径になる。または、曲がり始めの速さが計画の速さ × `PLAN_OVERSPEED` を超えている（ブレーキの距離が足りなかったときなど） |
| レーンチェンジ | 2つの条件を満たす L が見つからない。または、曲がり始めの速さが計画の速さ × `PLAN_OVERSPEED` を超えている |
| クランクの円弧の途中 | 外側の白線が見えた → 元の 121 / 161。曲がり終わっても線が見えない → 元の 120 / 160 |
| レーンチェンジのS字の後 | 変える側の端にだけ線が見えた → 元の 400 / 700 |
| 電源を入れた時（setup） | `config.h` の車の値が計算に使えない範囲（例えば `V_MAX_MPS` が 0、`SERVO_SPEED_DPS` が 10 以下）→ この走行の間は、速さの推定を使う処理をすべて元の表の動きにする（`model_check_config`） |
| ラインで速さを測った時 | 測った速さが推定の 0.6 倍〜1.67 倍の外になることが 2回続いた → この走行の間は元の表の動きにする |

### 2-8. 入れていないもの・計算で決まる限界

- **坂**：Basicマイコンカーには坂を検出するセンサ（傾きセンサやエンコーダ）がありません。そのため、坂専用の処理は入れていません。上り坂で遅くなると、速さの推定が実際より速くなります。次のクロスライン・ハーフラインで測り直すので、ずれはそこで直ります。
- **急なカーブの手前の限界**：センサは後輪の軸より `SENSOR_TO_REAR_AXLE_M`（250mm）前にあるだけなので、カーブが始まる所はセンサが着く直前まで分かりません。そのため、グリップの範囲で曲がれる直線の速さには上限があり、`v = √(横のグリップ × カーブの半径 + 2 × 前後のグリップ × 気づいてから後輪がカーブに着くまでの距離)` です。初期値の車（横 7.2 m/s²、前後 5.4 m/s²）で半径 0.6m なら約 2.6 m/s です。これより速い直線から急なカーブに入ると、どの方法でも一度ふくらみます。`TRACE_SAFE_RADIUS_M` にコースで一番急なカーブの半径を入れると、直線の速さをこの上限までに抑えます（2-10）。コースの地図を覚えて走る方法（2周目から速くする方法）なら超えられますが、今回は入れていません。
- **クランクの手前の限界**：クロスラインを見つけてから曲がり角までの距離で、全開から円弧の速さまで落とせる速さには上限があります（`v = √(円弧の速さ² + 2 × 前後のグリップ × 距離)`）。初期値の車でクロスラインから 0.5m なら、ちょうど 3.0 m/s ほどです。本当の出力100%の速さが `V_MAX_MPS` より 10% 速いと、どの方法でも減速しきれません（8 章）。
- **レーンチェンジの速さの精度**：S字の間はセンサを見ずに、推定した距離だけで走ります。推定した速さが 5% ずれると、横に動く量はおよそ 10% ずれます（30cm なら 3cm）。`LANE_DIST_ERR` の分は経路で吸収します。それより大きくずれると、S字の後の線の探し方（2-4）で直すことになります。

### 2-9. 線の形の推定（`USE_NEW_LINE_SHAPE`）

- **元の方法・`USE_NEW_STEER` の問題**：センサは 10mm おきで、線の位置は 5mm きざみでしか分かりません。そのきざみのまま角度を決めると、カーブの途中でもハンドルが2つの角度を行き来します。また、指令を出してからサーボが動き終わるまで 10〜20ms 遅れるので、3m/s では 3〜6cm 進んでから曲がり始めます。
- **新しい方法**：センサの所での「線の横の位置 z1、線の向き z2、線の曲がり具合 z3」の3つを、毎ms 推定します（`planner.ino` の `line_obs_update`。オブザーバと呼ばれる方法です）。z2 と z3 は、線の位置の1回微分と2回微分にあたります。
  1. **予測**：車が ds 進む間に、自分のハンドルで曲がった分だけ線は反対へずれて見えます。`z1 += (z2 − Ls·κ)·ds`、`z2 += (z3 − κ)·ds`。κ は車が本当に曲がっている曲率で、指令ではなく、サーボの遅れを計算した「サーボの本当の角度の推定」から求めます。横すべりしているときは、摩擦円で縮めた曲率を使います。
  2. **直す**：センサで見た線の位置との差 r に、`3p·ds`、`3p²·ds`、`p³·ds` をかけて z1、z2、z3 に足します（p = `LINE_OBS_BAND`、12/m）。この係数は、推定の誤差が距離 1/p（約 8cm）ごとに同じ割合で小さくなり、行き過ぎも振動もしない組み合わせです（極を3つとも −p に置く設計）。
  - 自分の動きで説明できる分を引いて、残った分だけを線の曲がりとみなすので、きざみやハンドルの揺れに引きずられにくくなります。
  - **センサのきざみの幅**：センサは 10mm おきなので、同じ並びに見える線の位置には 2〜8mm の幅があります。その幅の中のどこに線があるかは、センサでは分かりません。そこで、差 r が `LINE_OBS_DEADZONE_M`（2mm）以内なら直さず、超えた分だけで直します。0 にすると、推定がきざみの間を行き来して、カーブの途中でハンドルと速さが揺れました（`USE_NEW_CURVE_PREVIEW` も 1 のときだけ使います）。
  - 線が 20ms 以内だけ見えなくなった場合（大曲がりに入った時など）は、予測だけで続けます。それより長く見えなかったら、推定をやり直します。
- **ハンドルの決め方**（`line_obs_angle`）：今出す指令が効くのは `STEER_LEAD_S`（15ms）後です。その間に進む距離 d だけ先の、線の横の位置と向きを推定から予測します（`eL = z1 + (z2 − Ls·κ)·d + (z3 − κ)·d²/2`、`z2L = z2 + (z3 − κ)·d`）。遅れの分を先回りするので、カーブの入口で切り遅れません（スミス予測器と同じ考え方）。
  - `USE_NEW_CURVE_PREVIEW` も 1 のとき：車が曲率 κ で曲がると、センサの所の線のずれは `dz1/ds = z2 − Ls·κ` で変わります（予測と同じ式）。これがちょうど `−a·z1` になる曲率 `κ = (z2L + a·eL) ÷ Ls`（a = `LINE_STEER_GAIN`、10/m）で曲がります。線とのずれは 1/a = 10cm 進むごとに 1/e（約 37%）に減ります。ずれが 0 のときは `κ = z2 ÷ Ls` で、円のカーブでは z2 = Ls × 線の曲率 なので、ちょうど線の曲率で曲がります。車の向きは Ls 進むごとに 1/e ずつ線の向きにそろいます。
  - `USE_NEW_CURVE_PREVIEW` が 0 のとき：上の eL を `USE_NEW_STEER` と同じピュアパシュートの式 `κ = 2eL ÷ (Ld² + eL²)` に入れて角度にします。ピュアパシュートは線の向き z2 を見ないので、ずれが 0 を行き過ぎてハンドルが揺れます（模擬で、半径 1.5m のカーブで 4〜10°、0.3秒周期）。揺れの山に合わせて速さを落とすので、遅くなります。上の式はずれを急いで直さない分、カーブの入口で線が外へずれるので、z3 で先に減速する `USE_NEW_CURVE_PREVIEW` と組で使います（`USE_NEW_CURVE_PREVIEW` が 0 で上の式を使うと、S字 1.0m で外へ出ました）。
- **模擬で比べたもの**：線の位置を差分で微分する方法（α-β フィルタ）は、5mm のきざみを拾ってハンドルが振動しました。推定した線の形から Ld の所の位置を求め直す方法は、カーブの入口でふくらみました。どちらもやめて、上の方法にしています。
- **急なカーブでのライン検出**：急なカーブの途中で線を斜めに見ると、線1本がハーフラインと同じ並びに見えることがあります。推定した線の向き |z2| が `LINE_CHECK_MAX_ANGLE`（0.30rad = 17°）より大きく、しかもハンドルを `LINE_CHECK_MIN_STEER`（10°）より大きく切っている間は、クロスライン・ハーフラインを探しません。クロスライン・ハーフラインは直線にあるので、本物を見落とすことはありません。2つの条件の両方が外れることはまずないので、推定がおかしくなったときも直線では必ず探します。

### 2-10. カーブの先読み（`USE_NEW_CURVE_PREVIEW`）

- **`USE_NEW_TRACE_SPEED` の問題**：速さをハンドル角度で決めるので、減速が始まるのはハンドルを切った後です。その時には後輪はもうカーブに入っています。
- **新しい方法**（`speed_model.ino` の `trace_motor_preview`）：目標の速さを、次の3つのうち一番遅いものにします。
  1. サーボの本当の角度の推定から求めた曲率で、横すべりしない速さ（`PREVIEW_CURV_FILTER_S`、0.1秒でならす）。ハンドルの揺れ1回分でならすので、揺れの山ではなく平均の曲がり具合で速さが決まります。前の版は 30ms でならしていたので、山に合わせて速さを落としていました。グリップを設定より大きく見ていた場合は、横すべりして線から外へずれ、ハンドルを大きく切るので、ここで減速します（z3 だけで速さを決めると、横のグリップ −20% のときにカーブ 1.0m で外へ出ました）
  2. 2-9 で推定した、センサの所の曲がり具合 z3 で横すべりしない速さ。センサは後輪より `SENSOR_TO_REAR_AXLE_M` 前にあるので、後輪がカーブに着く前に減速を始められます。`PREVIEW_RATIO` を 0 より大きくすると、そこまでの距離で減速できる分だけ遅くブレーキをかけます（初期値 0 = すぐにその速さにする。一番安全）
  3. `TRACE_SAFE_RADIUS_M` による直線の速さの上限（0 なら使わない。2-8）
- **加速と減速の出し方**：目標の速さに次の1msで着く出力を計算します（デッドビート制御）。
  - 加速は、摩擦円で横に使っている分を引いた残りまでにします（`√(1 − (横の加速度 ÷ 横のグリップ)²) × 前後のグリップ`）。横の加速度は、指令ではなくサーボの本当の角度の推定で計算します。そのため、カーブの出口ではハンドルが戻るのに合わせて、自動で加速が強くなります。
  - 減速は、前後のグリップ `GRIP_LONG_MPS2 × PLAN_GRIP_RATIO_LONG` まで使います（摩擦円で弱めません）。模擬では、摩擦円で弱めると半径 0.8m のカーブで減速が足りずに外へ出ました。
- **左右の出力**：車の中心の速さは左右の出力の平均で決まります。外輪が 100% を超えるとき、`USE_NEW_TRACE_SPEED` は比を保って両方を下げるので、全開で曲がると中心の速さが落ちます（半径 1m で約 7%）。ここでは平均を保ち、左右の差の方を ±100% に収まるまで小さくします（`drive_center`）。
- **速さの推定の改善**：このスイッチを 1 にすると、速さの推定（2-1）も、サーボの本当の角度と摩擦円を使って計算します。曲がりながらブレーキをかけてタイヤがすべると、前後の減速も弱くなるのを計算に入れるためです。

### 2-11. 減速の距離を全部使う（`USE_NEW_BRAKE_RANGE`）

- **`USE_NEW_CRANK_BRAKE` / `USE_NEW_LANE_BRAKE` だけの場合**：ラインを通過し終わってから、距離を数え始めて減速を計算します。また、残りの距離は「曲がり角の線（中央線の切れ目）まで」です。
- **新しい方法**：
  1. ラインを見つけた瞬間から、距離をラインの幅の分マイナスから数え始め、その時の速さの推定で減速の計算を始めます。通過し終わったら、測った速さで計算し直します。ライン1本分（40mm）早くブレーキをかけ始められます。
  2. 曲がり角の線（中央線の切れ目）を見つけた後も、円弧（S字）に入るまでに `待つ距離 + 速さ × サーボの遅れ` だけ進みます。この距離も減速に使います（setup で、入る速さで計算しておく）。
  3. 円弧に入れるかの判断（`PLAN_OVERSPEED`）を、今の速さではなく、2 の距離を減速した後の速さで行います。
- **模擬での結果**（ほかのスイッチはすべて 1、7通りの平均）：クランク 1.0m で 1874 → 1841ms、0.5m で 1597 → 1595ms（横Gの最大 144% → 122%）、レーンチェンジは 0.5m・1.0m とも 2ms 短くなりました。

### 2-12. ハードウェアが設定と合っていないときの動き（冗長性）

`config.h` の値が実際の車と少しずれていても走れるように、次のようにしています。

| 備え | 内容 |
|---|---|
| 設定の確認 | setup で、車の値が計算に使える範囲にあるかを調べます。範囲の外なら、この走行の間は速さの推定を使う処理をすべて元の表の動きにします（2-7） |
| 速さの測定の確認 | 測った速さが推定の 0.6 倍〜1.67 倍の外なら、速い方の値を使います。2回続いたら元の表の動きにします（2-1） |
| 計算の確認 | 計算の結果が数でない値（0 で割った結果など）になったら、その値を使いません（`finite_f`）。速さの推定は 0 から、線の推定は最初からやり直します。モータ出力はその1msだけ 0 にし、ハンドル角度は 0 にします。ハンドル角度は必ず ±`SERVO_MAX_ANGLE` の中に収めます |
| 推定の範囲 | 線の向きは ±0.6rad、線の曲がり具合はハンドルを最大に切った時の2倍までに収めます。それを超える値は、センサの読み間違いか推定のずれです |
| 測定の混ぜ方 | 推定と測定を誤差の大きさで混ぜるので（2-1）、どちらかが少しずれても、もう一方で半分以上直ります |
| 経路の余裕 | レーンチェンジのS字は、走った距離が `LANE_DIST_ERR` の割合だけ短くても新しい車線に入る形にします（2-4）。クランクの円弧とS字は、コースの端から `COURSE_MARGIN_M` を残します |
| 元の方法に戻る | 計画どおりに曲がれないと分かったら、元のプログラムの方法で曲がります（2-7） |

模擬で本当の値を ±10%、±20% ずらした結果は 8 章にあります。

### 2-13. 応答の速さ

- センサを読んでからハンドルとモータの出力を出すまでは、すべて同じ 1ms の割り込みの中で行います。読んでから出すまでの遅れは 1ms 以内です。
- サーボの遅れ（10〜20ms）は、2-9 の予測で先回りします。
- 毎ms 行う計算のくり返し（ループ）は、センサ8個から線の位置を求めるものと、表からセンサの値を探すもの（元のプログラムと同じ）だけです。時間のかかる計算は、setup で1回だけ行って結果を覚えておきます。
  - ピュアパシュートの Ld（`pursuit_ld`）、線の曲がり具合の上限（`obs_k_lim`）、レーンチェンジの経路の表（17通り）、クランク・レーンチェンジで円弧に入るまでの距離
  - クランクの円弧の計算（二分法）は、曲がり角の線を見つけた時に1回だけ行います。
- サーボの遅れの計算は、32個の値を入れる輪の形のバッファ（リングバッファ）で、1ms に1つ書いて1つ読むだけです。
- 1ms ごとの計算は、新しいスイッチをすべて 1 にしても、三角関数が5回ほど、平方根が5回ほどと、足し算・かけ算が数百回です。48MHz の RA4M1（浮動小数点の回路あり）で 0.1ms ほどと見積もっています（実機では測っていません）。

### 2-14. クランクを素早く曲がる（`USE_NEW_CRANK_QUICK`）

全国大会の車のように「クランクの手前で少しだけ減速し、短い時間で 90°曲がり、すぐに真っすぐに戻る」走り方です。

- **なぜ小さい半径か**：センサが後輪の軸から遠い（`SENSOR_TO_REAR_AXLE_M` 0.46m）車は、曲がり角の線を見つけた時、後輪はまだ 0.46m 手前にいます。すぐに曲がると内側の角を切り、遅く曲がると外へ出ます。その間の「曲がり始めてよい位置の幅」は、半径が小さいほど広く（ハンドル 42〜50°で約 3.5cm）、半径を大きくすると狭くなります（`USE_NEW_CRANK_TURN` だけのときの半径 0.26m では幅がほぼ 0 で、模擬では内側の角を切りました）。そこで、幅が `CRANK_QUICK_WINDOW_M`（0.030m）以上ある一番大きい半径を選び、幅の真ん中から曲がり始めます。今の車の値では半径 0.18m（ハンドル 41.6°）、曲がる速さ 1.07m/s です。
- **減速**：`USE_NEW_CRANK_BRAKE` と同じく、全開で走り、ぎりぎりでブレーキをかけて、曲がる速さにします。
- **曲がり角の線で速さを測り直す**：曲がり角の線（曲がる側へ延びる中央線、幅 `CENTER_LINE_WIDTH_M`）を通り過ぎる時間で速さを測り直し、曲がり始める位置を決め直します。クロスラインは速いときに通るので 1ms の数え方で ±10% ほどずれますが、ここは減速した後なので数%で済みます。
- **線を見つける位置**：センサは曲がり角の線の中心ではなく、手前の端（`CENTER_LINE_WIDTH_M` の半分 ＋ `LINE_SEEN_EXTRA_M` の半分）で線を見つけるので、その分も入れて曲がり始める位置を決めます。
- **すぐ真っすぐに戻る**：曲がっている間、サーボの本当の角度の推定から、車の向きが変わった角度を足していきます。「今ハンドルを戻し始めても、戻りきるまでにさらに曲がる角度」を足して 90°になった所でハンドルを 0 に戻し始めます。戻るにつれて加速し、線が見えたら通常走行に戻ります。
- **元の方法に戻る場合**：曲がり始めてよい位置の幅がまったくない車の値（`CAR_FRONT_M` 0.47m など）のときと、速すぎて間に合わないときは、元の方法（pattern 110 / 150）で曲がります。
- **`CAR_FRONT_M` について**：この方法は、センサや車体の前の部分がコースの外の上を通ることを前提にしています。大会の規則で「タイヤがコースから出たらコースアウト」なら、`CAR_FRONT_M` は前輪の前の端まで（模擬では 0.18m）にします。車体全体がコース上にないといけない規則なら、0.46m 先にセンサがある車ではどの方法でもクランクを曲がれません（計算上、曲がり始めてよい位置がない）。
- **模擬での結果**（`CAR_FRONT_M` 0.18、クロスライン 20mm、`LINE_SEEN_EXTRA_M` 0.008、`USE_NEW_BRAKE_RANGE` も 1、7通りの平均、ほかは今の `config.h` の値）：

  | 方法 | 左クランク | 右クランク |
  |---|---|---|
  | 元の方法（スイッチ 0） | 7回とも失敗（内側の角を切る） | 7回とも失敗 |
  | `USE_NEW_CRANK_TURN`（大きい円弧） | 7回とも失敗（内側の角を切る） | 7回とも失敗 |
  | `USE_NEW_CRANK_QUICK` | 1777 ms、失敗 0/7 | 1777 ms、失敗 0/7 |

  90°曲がるのにかかる時間は約 0.28 秒で、ハンドルを戻し始めてから約 0.05 秒で車の向きのずれが 1°以下になりました。
  本当の値が設定とずれた場合（`QUICK` のみ、失敗の数/7）：`v_max` −10% 0、+10% 2、サーボの速さ 450°/s 0、サーボの遅れ 20ms 0、センサの位置 −2cm〜+4cm 0、−4cm 7、前後のグリップ −10% 0、横のグリップ −10% 0、時定数 0.2s 0。
  `CRANK_QUICK_WINDOW_M` を 0.020 にすると 23ms 速くなりますが、`v_max` +10% で 4/7、センサ −2cm で 2/7 失敗しました。
  センサが後輪に近い車（0.30m）では、`USE_NEW_CRANK_TURN` の大きい円弧の方が速く（1741 ms と 1790 ms）、`QUICK` は使わない方がよい結果でした。

## 3. 新しいアルゴリズムを使う前に測る値

ログに速さの推定値を出すため、`config.h` の `LOG_SPEED_MODEL` を `1` にしておきます。ログの最後に次の3列が増えます。調整が終わったら `0` に戻してかまいません。

| 列 | 内容 |
|---|---|
| `speed_mm_s` | 推定した速さ [mm/s] |
| `dist_mm` | ラインの終わりからの距離 [mm] |
| `vmax_mm_s` | 出力100%の速さとして使っている値 [mm/s]（`USE_NEW_VMAX_LEARN` が 1 のとき、ラインを通るたびに変わる） |

### 3-1. 車体の寸法（定規で測る）

| 設定 | 測る所 | 単位 |
|---|---|---|
| `WHEELBASE_M` | 前輪の軸の中心から後輪の軸の中心まで | m（170mm なら `0.170f`） |
| `TREAD_M` | 左右の後輪の、タイヤの幅の中心どうしの距離 | m |
| `SENSOR_TO_REAR_AXLE_M` | 後輪の軸の中心から、センサの発光部・受光部の中心まで（前向きの距離） | m |
| `SENSOR_X_MM` | 8個のセンサの左右の位置。車体の中心が 0、右がプラス。左端（bit7）から順に書く | mm |
| `CAR_FRONT_M` / `CAR_HALF_WIDTH_M` | コースの外に出てはいけない部分の、後輪の軸からの前の端までの距離と、幅の半分（下を参照） | m |
| `SERVO_MAX_ANGLE` | 計算で使ってよいハンドル角度の上限。サーボやタイヤが車体に当たらない角度 | 度 |

`CAR_FRONT_M` と `CAR_HALF_WIDTH_M` は、大会の規則で「コースアウト」が何を指すかで変わります。
- タイヤだけがコース上にあればよい場合：前輪の軸までの距離と、タイヤの外側までの幅の半分
- 車体全体がコース上にないといけない場合：車体の一番前の端までの距離と、車体の一番外側までの幅の半分

広い値を入れるほど安全で、遅くなります。

### 3-2. サーボ（`SERVO_SPEED_DPS` / `SERVO_DEAD_S`）

- `SERVO_SPEED_DPS`：サーボの仕様書の「動作速度」から計算します。例えば「0.10秒/60度」なら `60 ÷ 0.10 = 600`。仕様書の値は負荷なしの値で、タイヤが床に着いていると遅くなります。
- 実際に測る方法：スマートフォンのスロー撮影（240コマ/秒など）で、ハンドルを 0度から 30度へ切ったときを撮ります。動き始めから止まるまでのコマ数を数え、`30 ÷ (コマ数 ÷ 240)` が速さです。指令を出した時刻が分かるように、同時に LED を点ける処理を入れておくと、指令から動き始めまでのコマ数で `SERVO_DEAD_S` も測れます。
- 分からないときは遅めの値（例えば 400）を入れると安全です。模擬では、本当の速さが設定の 2/3 でも失敗しませんでした。

### 3-3. ラインの幅とコースの寸法

| 設定 | 測る所 |
|---|---|
| `CROSS_LINE_WIDTH_M` | クロスラインの、進行方向の「見える幅」（下を参照） |
| `HALF_LINE_WIDTH_M` | ハーフラインの、進行方向の「見える幅」 |
| `CROSS_TO_CRANK_M` | クロスラインの終わり（車から見て奥側の端）から、クランクの曲がり角の白線まで |
| `HALF_TO_LANE_M` | ハーフラインの終わりから、中央線が切れている所まで |
| `COURSE_WIDTH_M` | コースの幅 |
| `LANE_SHIFT_M` | 古い車線の中心線と、新しい車線の中心線の間隔 |
| `LANE_SECTION_M` | 中央線が切れてから、コースが新しい車線だけの幅に戻るまでの長さ |

大会のコースでは距離が変わることがあります。距離が分からないときは、大会のルールに書かれている範囲の**一番短い値**を入れておくと安全です。

**クランク・レーンチェンジが何回か出てくるコース（`COURSE_LIST_USE = 1`）**：1つのコースで、クロスラインから曲がり角までの距離やラインの幅が、クランクごとに違うことがあります（例：JMCR2027 地区大会のコース図では、クランク3つが 800mm・700mm・600mm、クロスラインの幅が 20mm・30mm・40mm）。このときは、`config.h` の `COURSE_LIST` に、コース1周分のクランクとレーンチェンジを、走る順に1行ずつ書きます。上の表の `CROSS_TO_CRANK_M`・`HALF_TO_LANE_M`・`CROSS_LINE_WIDTH_M`・`HALF_LINE_WIDTH_M` は使われません。

```c
const CourseSpot COURSE_LIST[] = {
    // 種類  距離     線の幅    向き
    { 'C', 0.800f, 0.020f, 'R' },   // 0. 中央の右クランク
    { 'C', 0.700f, 0.030f, 'L' },   // 1. 左上の左クランク
    { 'H', 0.400f, 0.040f, 'R' },   // 2. 上の右レーンチェンジ
    { 'C', 0.600f, 0.040f, 'R' },   // 3. 右下の右クランク
};
const int COURSE_START_ROWS[] = {
    0,    // 外側の直線からスタート（最初は 0 の行）
    1,    // 内側の直線からスタート（最初は 1 の行）
};
```

- 種類：`'C'` はクランク（クロスライン）、`'H'` はレーンチェンジ（ハーフライン）です。
- 距離：コース図の寸法（クロスライン・ハーフラインの終わりから、曲がり角・中央線の切れ目まで）をそのまま書きます。
- 線の幅：コース図の「幅○○mm」をそのまま書きます。センサに広く見える分は、どの線でもほぼ同じなので、`LINE_SEEN_EXTRA_M` に1つだけ入れます。測り方は下の「見える幅の合わせ方」と同じで、`LINE_SEEN_EXTRA_M = 見える幅 − コース図の幅` にします。**0 のままだと速さを少なく見積もり、ブレーキが遅れます**（模擬では、20mm の線で 0 にすると 7回とも曲がりきれませんでした）。
- 向き：右は `'R'`、左は `'L'` です。
- `COURSE_START_ROWS`：スタートしてから最初に来るのが表の何行目か（0 から数える）です。表は1周分なので、最後の行の次は 0 の行に戻ります。スタートの位置が何通りかあるときは、あり得るものを全部書きます。

**スタートの位置の決まり方**：スタートの位置が1つに決まるまでは、あり得る行の中で一番短い距離と一番広い線の幅を使います（ブレーキが早くなる側）。クランクで曲がった向きと、ハーフラインの向きを表と比べて、合わない位置を外していきます。上の例では、1つ目のクランクを右に曲がれば外側、左に曲がれば内側からのスタートと決まり、2つ目からは表の値どおりに走ります。

- 1つ目のクランクは、位置が決まる前に減速するので遅くなります。模擬（右 0.8m・幅20mm → 左 0.7m・幅30mm の2つのクランク）では、スタートの位置が分かっている場合の 2972ms に対して 3799ms でした。遅くなる分のほとんどは線の幅の違い（20mm と 30mm）から来ます。広い方の幅で速さを計算するので、速さを 36% 多めに見積もって、早めに強く減速するためです（距離の違い 0.8m と 0.7m だけなら、ほとんど遅くなりません）。
- 走る前にどちらからスタートするか分かっているときは、`COURSE_START_ROWS` をその行だけにすると、1つ目のクランクから表の値どおりに走ります。
- どの位置とも合わなくなったら（線の見間違いなど）、それより後はずっと、表の中でその種類の一番短い距離と一番広い線の幅を使います。
- クランクの向きは曲がり角に着くまで分からないので、**表の順番を間違えると、そのクランクでは間違えた距離のまま減速します**。順番はよく確かめてください。
- 練習のコースなど、クランク・レーンチェンジが1つずつで距離が同じなら、`COURSE_LIST_USE = 0` にして上の表の4つの値を使えます。

**見える幅の合わせ方**：センサは白線の端より少し外側でも白と判定するので、線は実際の幅より広く見えます。この幅がずれると、測った速さがそのままずれます（幅が 10% ずれると速さも 10% ずれる）。次の手順で合わせます。

（`COURSE_LIST_USE = 1` のときは、6 で求めた幅から、そのクロスラインのコース図の幅を引いた値を `LINE_SEEN_EXTRA_M` にします）

1. `LOG_SPEED_MODEL = 1`、DIPスイッチを 3（100%）にします。
2. 長い直線の途中にクロスラインを置き、その 1.0m 先に白いテープを横に貼ります。
3. 全開でクロスラインを通過させます。
4. ログで、クロスラインの形が消えた時刻と、テープが見えた時刻の差 Δt[s] を読みます。本当の速さは `1.0 ÷ Δt` です（ログは10msごとなので、1m 先なら誤差は 3% ほど。2m 先にするとさらに小さくなります）。
5. 同じ走行で、クロスラインを通過した直後の `speed_mm_s`（測り直した速さ）を読みます。
6. `CROSS_LINE_WIDTH_M = 今の値 × 本当の速さ ÷ 測り直した速さ` に直します。3回ほどくり返して平均を使います。
7. ハーフラインも同じ手順で合わせます。

### 3-4. 最高速度 `V_MAX_MPS`（出力100%での速さ）

1. DIPスイッチを 3（100%）にします。電池は大会で使うのと同じ充電の状態にします。
2. 長い直線（2m以上）の途中に、間隔を測ったクロスラインを2本置きます。例えば 1.5m 間隔にします。クロスラインがなければ、白いテープを横に貼っても構いません。
3. 1本目までに十分加速できる位置からスタートさせます。
4. ログの `sensor` 列で、クロスラインの形（`'111xx111` のような行）が現れた時刻 `ms` を2本分読み取ります。
5. `V_MAX_MPS = 間隔[m] ÷ (2本目の時刻 − 1本目の時刻)[s]`
   - 例：1.5m を 0.52秒 → 2.88 m/s
   - ログは10msごとなので、間隔が長いほど誤差が小さくなります。

電池の電圧で変わるので、充電したてと、何回か走った後の両方を測っておきます。差が大きいときは、`USE_NEW_VMAX_LEARN` を使うと走りながら直せます（4-4）。

### 3-5. 時定数 `MOTOR_TAU_S`

1. 3-4 と同じ直線で、スタートから全開で走らせます。
2. スタートから 0.3m、0.6m、0.9m … の位置に白いテープを貼り、ログで通過時刻を読みます。
3. 区間ごとの速さを計算し、`V_MAX_MPS × 0.63` に達した時刻を読みます。その時刻（秒）が `MOTOR_TAU_S` です。
4. 簡単に済ませる方法もあります。`LOG_SPEED_MODEL = 1` で走らせ、クロスラインを通過した直後の `speed_mm_s` の変化を見ます。クロスラインで測り直した瞬間に推定値が大きく跳ねる場合は、`MOTOR_TAU_S` か `V_MAX_MPS` が合っていません。
   - 測り直した値の方が**小さく**跳ねる → 推定が速すぎる。`V_MAX_MPS` を下げるか `MOTOR_TAU_S` を大きくする
   - 測り直した値の方が**大きく**跳ねる → 推定が遅すぎる。逆に直す
   - 1回の測り直しには 7〜8% の誤差があるので（2-1）、3回以上の平均で判断します。

### 3-6. タイヤのグリップ（`GRIP_LONG_MPS2` / `GRIP_LAT_MPS2`）

**前後（`GRIP_LONG_MPS2`）**：止まった状態から全開で発進すると、最初はタイヤが空回りする手前の加速度で進みます。

1. スタート位置から 0.20m 先に白いテープを横に貼ります（センサの位置から測る）。
2. 全開でスタートさせ、ログでスタート（pattern 20 になった時刻）からテープが見えた時刻までの時間 t[s] を読みます。
3. `GRIP_LONG_MPS2 = 2 × 0.20 ÷ t²`
   - 例：0.26秒 → 5.9 m/s²
   - モータの力で決まっている場合（タイヤが空回りしない場合）は、この値は小さめに出ます。小さめに出る分には安全です。

**横（`GRIP_LAT_MPS2`）**：半径の分かっているカーブを、だんだん速くして回します。

1. 半径 R の分かっているカーブ（例えば 0.6m）を用意します。
2. 元のプログラム（スイッチ0）で、DIPスイッチで出力を下げて走らせ、カーブで外にふくらむ（pattern 30〜45 が出る）か見ます。
3. ふくらみ始める直前の出力 p[%] を見つけます。その出力での速さは、およそ `p/100 × V_MAX_MPS` です。
4. `GRIP_LAT_MPS2 = 速さ² ÷ R`
   - 例：R = 0.6m で 2.1 m/s → 7.4 m/s²

どちらも、測った値をそのまま入れます。余裕は `PLAN_GRIP_RATIO_LAT` / `PLAN_GRIP_RATIO_LONG`（0.9）で持たせているので、ここで下げる必要はありません。

## 4. 新しいアルゴリズムを1つずつ有効にする

必ず下の順番で1つずつ（決まった組は2つ一緒に）`1` にして、それぞれ確かめてから次に進みます。2つ以上を同時に変えると、うまくいかなかったときに原因が分からなくなります。

### 4-1. 速さの推定を確かめる（スイッチは 0 のまま）

1. `LOG_SPEED_MODEL = 1` にして、クロスラインとハーフラインのあるコースを走らせます。
2. ラインを通った直後に `speed_mm_s` がどれだけ跳ねるかを見ます。跳ねる量が 10% より大きいことが多いときは、3-3〜3-5 をやり直します。
3. `dist_mm` が、クロスラインの終わりからクランクまでで `CROSS_TO_CRANK_M` とおよそ同じ値になっているかを見ます（pattern 110 / 150 になった行）。

### 4-2. クランク（`USE_NEW_CRANK_BRAKE = 1` と `USE_NEW_CRANK_TURN = 1`）

1. `CRANK_ENTRY_MPS` は `0.0f`（自動）のままにします。
2. クランクのあるコースを5回走らせ、5回ともクランクを抜けられるか確かめます。
3. ログで次の順に pattern が変わっているかを見ます。
   - 102 / 103：`motor_l` / `motor_r` が「100 → マイナス（ブレーキ）→ 一定の値」の順に変わる
   - 112 / 152：円弧で曲がっている。`handle` が計算した角度（例えば 42度）で一定になる
   - 20：通常走行に戻った
4. 失敗の見分け方と直し方：

| ログの様子 | 意味 | 直し方 |
|---|---|---|
| 112 / 152 にならず 110 / 150 になる | 計画をやめて元の方法で曲がった。ブレーキが足りずに速すぎた | `CRANK_BRAKE_MARGIN_M` を 0.02 増やす。`CROSS_TO_CRANK_M` が実際より長くないか確かめる |
| 112 / 152 の後に 121 / 161 | 円弧の途中で外側にはみ出した | `COURSE_MARGIN_M` を 0.01 増やす。または `PLAN_GRIP_RATIO_LAT` を 0.05 下げる |
| 112 / 152 の後に 120 / 160 | 曲がり終わっても線が見つからなかった | `SERVO_SPEED_DPS` が実際より速くないか確かめる（3-2） |
| ブレーキの区間でタイヤが滑って向きが乱れる | ブレーキが強すぎる | `CRANK_BRAKE_POWER` を -60 → -40 のように弱める |

5. 5回とも抜けられたら、速くしていきます。1回に1つずつ変え、それぞれ5回走らせます。
   - `PLAN_GRIP_RATIO_LONG` を 0.05 ずつ上げる（1.0 まで）
   - `PLAN_GRIP_RATIO_LAT` を 0.02 ずつ上げる（1.0 まで）
   - `COURSE_MARGIN_M` を 0.005 ずつ下げる（0 まで）
   - 失敗したら1つ前の値に戻します。

### 4-3. レーンチェンジ（`USE_NEW_LANE_BRAKE = 1` と `USE_NEW_LANE_STEER = 1`）

1. `LANE_ENTRY_MPS` は `0.0f`（自動）のままにします。
2. 左右のレーンチェンジを5回ずつ走らせます。
3. ログで 300〜310 / 600〜610（減速）→ 360〜370 / 660〜670（S字）→ 380〜390 / 680〜690（線を探す）→ 20 の順になっているかを見ます。
4. 失敗の見分け方と直し方：

| ログの様子 | 意味 | 直し方 |
|---|---|---|
| 360 / 660 にならず 320 / 620 になる | 計画をやめて元の方法で曲がった | `LANE_BRAKE_MARGIN_M` を 0.02 増やす。`LANE_SECTION_M` が実際より短くないか確かめる |
| 380 / 680 の後に 400 / 700 がよく出る | 横に動き足りない。推定した速さが実際より速い | `V_MAX_MPS` を下げる。`HALF_LINE_WIDTH_M` を合わせ直す（3-3） |
| 380 / 680 で、線が反対側の端に見えてからハンドルを切る | 行き過ぎた。推定した速さが実際より遅い | `V_MAX_MPS` を上げる。`HALF_LINE_WIDTH_M` を合わせ直す |
| 360 / 660 の途中でコースアウト | 古い車線の端か、区間の終わりではみ出した | `COURSE_MARGIN_M` を 0.01 増やす。`LANE_SECTION_M` と `LANE_SHIFT_M` を測り直す |

5. 5回ずつ成功したら、4-2 の 5 と同じ順で余裕を減らしていきます。

### 4-4. 出力100%の速さの学習（`USE_NEW_VMAX_LEARN = 1`）

3-3 でラインの見える幅を合わせてから使います。幅がずれていると、ずれた速さを正しいと思って学習してしまいます（模擬では、見える幅が 10% ずれた場合に失敗が増えました）。

1. コースを3周ほど走らせ、ログの `vmax_mm_s` を見ます。
2. ラインを通るたびに少しずつ変わり、`V_MAX_MPS` の ±10% の中で落ち着いていれば正しく動いています。
3. 通るたびに上下に大きく（10% 以上）ふれる場合は、測定を信じすぎています。`LINE_WIDTH_SD` を 0.03 → 0.05 に上げます（測定の誤差を大きく見るので、混ぜる割合 K が下がります）。
4. 電池の電圧で `V_MAX_MPS` がほとんど変わらないと分かっている場合は、`VMAX_LEARN_SD` を 0.10 → 0.05 に下げます。

### 4-5. 通常走行（`USE_NEW_TRACE_SPEED` → `USE_NEW_CURVE_SPEED` → `USE_NEW_STEER`）

この3つは、元の表（実機で調整されたもの）より速いとは限りません（2-5）。1つずつ 1 にして、周回のタイムを元と比べ、速くなったものだけを残します。

1. `USE_NEW_TRACE_SPEED = 1`：周回コースを5回走らせ、コースアウトしないことと、タイムを確かめます。
   - カーブで外にふくらむ（pattern 30〜45 が増える）→ `PLAN_GRIP_RATIO_LAT` を下げる
   - 直線でハンドルが小刻みに揺れて遅くなる → `TRACE_CURV_FILTER_S` を 0.03 → 0.06 に増やす
2. `USE_NEW_CURVE_SPEED = 1`：同じように確かめます。
3. `USE_NEW_STEER = 1`：直線でハンドルが左右に揺れる場合は、`TRACE_MIN_RADIUS_M` を大きくすると（例えば 0.6）、ハンドルの動きがおだやかになります。ただし急なカーブで線がセンサの外へ出やすくなります。

### 4-6. 加速の制限（`USE_NEW_TRACTION = 1`）

スタートやクランクの出口でタイヤが空回りしている場合に効きます。3-6 と同じ方法で、スタートから 0.20m のテープまでの時間を 0 と 1 で比べ、短くなった方を使います。

### 4-7. カーブの判断（`USE_NEW_LINE_SHAPE` → `USE_NEW_CURVE_PREVIEW`）と減速の距離（`USE_NEW_BRAKE_RANGE`）

1. `USE_NEW_STEER = 1` のまま `USE_NEW_LINE_SHAPE = 1` にします。
   - 直線でハンドルが揺れなくなり、カーブの入口で早めに切り始めれば正しく動いています。
   - カーブの入口でふくらむ → `STEER_LEAD_S` を 0.005 ずつ増やす（サーボが設定より遅い）
   - カーブの入口で内側に切れ込む、直線で左右に揺れる → `STEER_LEAD_S` を 0.005 ずつ減らす
   - 急なカーブの途中で pattern 100 / 200 / 500 になる（ラインと見間違えた）→ `LINE_CHECK_MAX_ANGLE` を 0.05 下げる
   - `USE_NEW_CURVE_PREVIEW = 1` にした後、カーブの途中でハンドルが左右に揺れる → `LINE_STEER_GAIN` を 2 ずつ下げる。線に戻るのが遅く、カーブの外へずれたままになる → 2 ずつ上げる（模擬では 8〜12 で同じくらい）
   - 線の幅が 20mm でない、センサの間隔が 10mm でない → `LINE_OBS_DEADZONE_M` を「同じ並びに見える位置の幅の小さい方 ÷ 2」にする（分からなければ 0.001）
2. `USE_NEW_TRACE_SPEED = 1` のまま `USE_NEW_CURVE_PREVIEW = 1` にします。
   - カーブの入口で、ハンドルを切る前に `motor_l` / `motor_r` が下がり始めれば正しく動いています。
   - 長い直線の後の急なカーブで外へふくらむ → `TRACE_SAFE_RADIUS_M` にそのカーブの半径を入れる（直線が遅くなるので、必要なときだけ）
   - カーブの手前で早く減速しすぎる → `PREVIEW_RATIO` を 0.2 ずつ上げる（1.0 まで）
3. `USE_NEW_BRAKE_RANGE = 1` にします（クランク・レーンチェンジの減速を 1 にしてある場合だけ変わります）。4-2、4-3 と同じように5回ずつ走らせ、`PLAN_OVERSPEED` で元の方法に戻る回数（110 / 150、320 / 620）が増えていないか確かめます。

## 5. 元の表（tables.h）を直接調整する場合

新しいアルゴリズムを使わない部分は、`tables.h` の表で調整します。

- `AM(角度, 左モータ, 右モータ)` の数値を変えます。表の1行が1つの段階です。
- 例：通常走行の段階3で、センサが `0x07`（右寄りの中程度のカーブ）のときに内輪をもっと減速したい場合
  1. `TRACE_SENSOR` で `0x07` が何番目かを見る → 6番目（0から数えて5）
  2. `TRACE_ACT` の `// pattern 23` の行の6番目 `AM( 19, 100,  57)` の右モータ `57` を変える
- 段階が上がる条件（直線が続く時間）は `config.h` の `TRACE_STAGE_UP_MS` です。

よくある症状と直す場所:

| 症状 | 直す場所 |
|---|---|
| 直線でハンドルが左右に揺れる | `TRACE_ACT` の 0x1c / 0x38 の角度（今は ±2）を小さくする |
| カーブで外にふくらむ | `TRACE_ACT` の内輪の値を下げる。または `TRACE_STAGE_UP_MS` を大きくして、速い段階に上がりにくくする |
| クランクで外にはみ出す | `CRANK_RAMP`（元の方法）か `PLAN_GRIP_RATIO_LAT` / `COURSE_MARGIN_M`（新しい方法）を直す |
| サーボの中心がずれている | `SERVO_CENTER` を 10 ずつ変える |

## 6. 書き換えた後に PC で確かめる方法（任意）

どちらも `g++` が必要です（Linux、macOS、Windows の WSL）。

### 6-1. 元のプログラムと同じ動きか（`tools/host_test/`）

`tools/host_test/compare.sh` を使うと、元のプログラムと動きが同じかどうかを PC で確かめられます。
新しいアルゴリズムのスイッチや表の数値を変えた場合は、元と動きが変わるので「不一致」と出るのが正しい結果です。
リファクタリングのように「動きを変えずに書き方だけ直した」ときの確認に使ってください。詳しくは `tools/host_test/README.md` にあります。

### 6-2. コースの模擬（`tools/course_sim/`）

`config.h` の値を変えたときに、クランク・レーンチェンジ・カーブを計算どおりに曲がれるかを PC で確かめられます。

いちばん手軽なのは、Web版のシミュレータ（https://ao81.github.io/mcr2026/simulator/）をブラウザで開く方法です。コース、スイッチ、`config.h` の新しいアルゴリズムの値、本当の車の値（グリップなど）を画面で選ぶと、その場で走らせて、車の動きとグラフを表示します。コマンドで使う場合は次のとおりです。

```sh
tools/course_sim/compare.sh                       # 元と新しい方法をまとめて比べる
tools/course_sim/run.sh all crank_l lane_r avg=1  # すべて新しくして、クランクとレーンチェンジだけ
tools/course_sim/run.sh all crank_l grip_lat=7.2 avg=1   # 本当の横のグリップが 10% 低かったら
```

実機で測った値を `config.h` に入れたら、まず模擬で失敗しないことを確かめてから実機で走らせると、試す回数を減らせます。詳しくは `tools/course_sim/README.md` にあります。

## 8. PC での模擬の結果

`tools/course_sim/compare.sh` の結果です（`config.h` の初期値、車の値は設定どおり、7通りのスタート位置の平均）。模擬の車は `config.h` の初期値なので、元のプログラムを調整した実機とは違います。比べ方の目安として見てください。

| コース | 元のプログラム | クランク・レーンチェンジだけ新しく | すべて新しく |
|---|---|---|---|
| クランク（クロスラインから 0.5m） | 7回とも失敗 | 1577 ms | 1595 ms |
| クランク（1.0m） | 7回とも失敗 | 1844 ms | 1841 ms |
| レーンチェンジ（ハーフラインから 0.5m） | 1732 ms | 1697 ms | 1706 ms |
| レーンチェンジ（1.0m） | 1912 ms | 1865 ms | 1875 ms |
| カーブ 半径 0.8m（直線 1.5m の後） | 7回とも失敗 | ― | 2226 ms |
| カーブ 半径 1.0m | 2256 ms | ― | 2322 ms |
| カーブ 半径 1.5m | 2777 ms | ― | 2694 ms |
| S字 半径 0.8m（90° ずつ） | 7回とも失敗 | ― | 2059 ms |
| S字 半径 1.0m | 2031 ms | ― | 2091 ms |
| S字 半径 1.5m | 2554 ms | ― | 2481 ms |

- **ハンドルの決め方を変えた結果**（2-9、2-10。前の版との差）：カーブ 0.8m 2286 → 2226ms、1.5m 2745 → 2694ms、S字 1.5m 2525 → 2481ms、1.0m は 2324 → 2322ms、S字 0.8m は 2051 → 2059ms です。クランク・レーンチェンジは 1ms 以内の差です。
- **計算で求めた一番速い時間との比較**：横のグリップの 90% までしか使わない条件で、直線で全開・カーブの手前でちょうど間に合うように全力のブレーキ・カーブの中は一定の速さ、という走り方の時間を計算すると、カーブ 0.8m は約 2223ms、1.0m は約 2332ms、1.5m は約 2715ms です（後輪の通る道を、センサの線より内側の半径 √(R² − 0.25²) の円とした概算。±20ms ほどの誤差があります）。新しい方法の時間はどれもこの ±1% に入っていて、グリップの 90% という条件の中では、これ以上はほとんど縮みません。
- **レーンチェンジでスタート位置によって遅くなる場合**：ハーフラインから 0.3m のコースで、スタート位置 1.40〜1.467m では新しい方法の方が 19〜21ms 速く、1.483m と 1.50m では 23〜24ms 遅くなります。遅い2つは、ラインの通過時間を 1ms 単位で数えた誤差で、測った速さが 5% 速く出た場合です（2.91 m/s を 3.05 m/s）。その分だけ実際より遅くレーンチェンジを走るうえ、横に動く距離が 3cm 足りず、大曲がりの表で線に戻ります。1ms より細かく時間を測れば小さくできます（センサの変化を `micros()` で記録するなど。実機で確かめる必要があるので、まだ入れていません）。

- **元のプログラムの方が速いもの**：カーブ・S字の半径 1.0m と、クランク 0.7m（元 1672ms、新しい方法 1728ms）です。どれも元のプログラムは横のグリップの 121〜123% を求めて横すべりしながら走っています（半径 1.0m のカーブの中で平均 104%、速さ 2.76 m/s。新しい方法は 2.59 m/s）。模擬はすべっても外へふくらむだけで、速さは落ちないので（`tools/course_sim/README.md` の 5-3）、実機でも同じとは限りません。新しい方法はグリップの 90%（`PLAN_GRIP_RATIO_LAT`）までしか使いません。1.0 にすると、カーブ 1.0m は 2294ms、S字 1.0m は 2074ms、レーンチェンジ 0.3m は 1637 → 1606ms です。実機で横のグリップを測って（3-6）、すべらないと分かった分だけ上げてください。
- **前の版との違い**：前の版はラインの通過時間に 2ms 足していたので（2-1）、測った速さが 5〜8% 遅く出ていました。そのため、計画より速くクランクやレーンチェンジに入り、余裕を使い切っていました。同じ測り方（1ms）にそろえて比べると、クランク 1.0m は 1874 → 1841ms、カーブ 1.0m は 2346 → 2324ms、1.5m は 2788 → 2745ms です。レーンチェンジ 1.0m は 1856 → 1875ms で、S字に距離の誤差の余裕（`LANE_DIST_ERR`）を入れた分だけ遅くなりました（0 にすると 1850ms）。
- **余裕をすべてなくした場合**（`PLAN_GRIP_RATIO_*` 1.0、`COURSE_MARGIN_M`・`*_BRAKE_MARGIN_M`・`LANE_DIST_ERR` 0）：クランク 0.5m 1573ms、1.0m 1784ms、カーブ 1.0m 2266ms、1.5m 2722ms でした。レーンチェンジは 7回とも失敗しました。初期値の余裕で失うのは、クランクで 20〜60ms です。
- **`USE_NEW_VMAX_LEARN`**：車の値が設定どおりのときは、0 の方が少し速くなりました（クランク 1.0m 1830ms、レーンチェンジ 1.0m 1868ms）。学習は、1回の測定の誤差（1ms の数え方）も少し取り込むためです。電池の電圧で速さが変わる場合に 1 にします。
- **クランクごとに距離が違うコース**（`crank2`：右クランク 0.8m・幅20mm → 左クランク 0.7m・幅30mm。3-3 の `COURSE_LIST` で `COURSE_START_ROWS` を 0 の行だけにした場合。車は 2026-11-19 より前の `config.h` の車体の値、すべて新しく）：1つの値 `CROSS_TO_CRANK_M = 0.8` だと、2つ目のクランクでブレーキが 0.1m 遅れて 7回中6回失敗しました。短い方の 0.7m・幅38mm にそろえると失敗はありませんが 3798ms、表を使うと 2972ms でした。表の1つ目の向きをわざと間違えた場合（数え間違えたとみて、2つ目は一番短い 0.6m を使う）は 3210ms で、失敗はありませんでした。スタートの位置を外側・内側の2通りにした場合（1つ目のクランクで決まる）は 3799ms で、失敗はありませんでした。
- **直線 1.5m の後の半径 0.6m のカーブ**：どの方法でも曲がりきれません（2-8）。`TRACE_SAFE_RADIUS_M = 0.6` にすると曲がれますが（2177ms）、直線が遅くなるので、カーブ 1.0m は 2496ms、1.5m は 3138ms になります。

### カーブを最高速のまま、ふらつかずに曲がる（2026-11-26）

`USE_NEW_STEER`・`USE_NEW_LINE_SHAPE`・`USE_NEW_TRACE_SPEED`・`USE_NEW_CURVE_SPEED`・`USE_NEW_CURVE_PREVIEW` の5つを 1 にしました。あわせて `LINE_OBS_DEADZONE_M` を 0.002 → 0.003 にし、カーブの入口でクロスライン・ハーフラインを探さない条件（`LINE_CHECK_MAX_CURV`・`LINE_CHECK_CURV_ANGLE`）を足しました。

ふらついていた理由（模擬で確認）：

- 元の表（tables.h）は、センサの形ごとにハンドル角度が決まっています。半径 1m のカーブでは、必要な角度は約 9° ですが、表には 2°（0x1c）と 11°（0x0e）しかないので、ハンドルが 2° と 11° を 0.1 秒ほどの周期で行き来していました。内輪の出力も 100% と 79% を行き来します。

### クロスラインの後、1回のブレーキで曲がる速さにする（2026-11-26）

前の動き（`USE_NEW_CRANK_ANY_COURSE` が 1、`CRANK_APPROACH_MPS` が 0）は、クロスラインを過ぎるとすぐにブレーキをかけ、曲がり角まで曲がる速さ（約 0.97 m/s）で走っていました。さらに、ブレーキの出力が `CRANK_BRAKE_POWER`（-40）のままなので、実際の減速が計算（`GRIP_LONG_USE` = 5.4 m/s²）より強いと、目標より大きく下がってから加速し直していました（模擬で減速を強くすると 1.72 → 0.50 m/s まで落ち、0.97 m/s に戻るまで約 0.5 秒。実車の CRK0099 も 0.97 の予定が 0.58 まで落ちた）。

直したこと：

- `CRANK_RULE_MIN_M`（0.500）：規則でクロスラインの終わりから曲がり角までは 500〜1000mm なので、一番近い 0.5m で曲がる速さになっていればよい。そこまでは全開で走り、0.5m − `CRANK_BRAKE_MARGIN_M` でちょうど曲がる速さになるように1回だけブレーキをかけます。コースの寸法（`COURSE_LIST`）は使いません。曲がり角が 0.5m より遠いときは、そこからは曲がる速さのまま走ります。0 にすると前の動き（すぐにブレーキ）です。
- `BRAKE_AT_GRIP`（1）：ブレーキの出力を、モデルの減速度がちょうど `GRIP_LONG_USE` になる値にします（`CRANK_BRAKE_POWER`・`LANE_BRAKE_POWER` より強くはしない）。減速はモータのモデルどおりになり、推定と実際の速さのずれもブレーキ中に縮みます。実際の減速が強い車でも、目標の速さで止まり、加速し直しません。0 にすると前の動きです。

模擬の結果（`crank_l`、7回の平均。前 → 後）。値を1つずつずらしたどの場合も、失敗は前も後も 0 です。

| 値 | 曲がり角まで 0.5m | 0.7m | 1.0m |
|---|---|---|---|
| そのまま | 2282 → 2119ms | 2485 → 2314ms | 2788 → 2607ms |
| `grip_long` 8（ブレーキが計算より強い） | 2327 → 2126ms | 2533 → 2329ms | 2834 → 2626ms |
| `grip_long` 4.5（ブレーキが計算より弱い） | 2298 → 2213ms | 2488 → 2364ms | 2791 → 2621ms |
| `v_max` 1.5 | 2529 → 2362ms | 2727 → 2563ms | 3049 → 2858ms |
| `tau` 0.2 | 2350 → 2234ms | 2554 → 2381ms | 2860 → 2647ms |

- クランクが2つのコース（`crank2`）：4247 → 3937ms。`V_MAX_MPS` を 1.0〜3.0 にずらしても（本当の値 1.7）失敗 0、どれも 260〜320ms 短くなりました。
- `grip_lat` 6、`tau` 0.1、`servo_dps` 400、`servo_dead` 0.02、`sensor_to_axle` 0.44・0.48、`spot` 0.002、クロスラインの幅 22mm・42mm でも失敗 0 です。
- `BRAKE_AT_GRIP` を付けずに `CRANK_RULE_MIN_M` だけにすると、ブレーキが計算より強い車（`grip_long` 8 以上）で、曲がり角が 0.5m のとき 7回中 5〜7回失敗しました。下がりすぎた速さを曲がり角の線で測り、`v_max` が小さいと直したため、その後の出力が上がって速すぎる速さで曲がり始めたためです。2つは一緒に使ってください。
- レーンチェンジ（`lane_l`）は、ハーフラインから中央線の切れ目までの距離を使って減速するので、時間は前と同じでした。
- 実機では、クロスラインの後のログで、速さが1回だけ下がってそのまま曲がり角に入っているかを見てください。曲がり角で速すぎるときは `CRANK_BRAKE_MARGIN_M` を大きくします。
