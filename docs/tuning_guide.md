# 実機での調整手順

このファイルは、実機がないとできない確認と数値の調整を、作業する順番に書いたものです。
数値はすべて `basic/config.h`（時間・速度・新しいアルゴリズムの設定）と `basic/tables.h`（センサ値ごとの表）にあります。

---

## 0. 今のプログラムの状態

| 項目 | 状態 |
|---|---|
| リファクタリング | 走行の動きは元のプログラムと同じ。PC 上で 23000通りの入力を与え、1ms ごとの出力がすべて一致することを確認済み |
| 新しいアルゴリズム | `config.h` のスイッチ `USE_NEW_CRANK_BRAKE` / `USE_NEW_LANE_BRAKE` / `USE_NEW_TRACE_SPEED` で切り替える。初期値はすべて `0`（元の動き） |
| 実機での確認 | まだしていない |

> **注意1** `AUTO_STOP_MS` は `5000`（5秒）のままです。スタートから5秒で必ず止まります。コースを1周するのにかかる時間より長くしてから走らせてください。
>
> **注意2** 自動停止（pattern 800, 801）やコースアウトで止まったときは、ログファイルがまだ閉じられていません。止まった後に**プッシュスイッチを押して** pattern 1001 にしてから電源を切ってください。押さずに電源を切ると、ログが残らないことがあります。

## 1. まず、リファクタリング後のプログラムが前と同じに走るか確かめる

1. Arduino IDE で `basic` フォルダの `basic.ino` を開きます。上のタブに `config.h`、`tables.h`、`hardware.ino` などが並んでいれば正しく開けています。
2. `config.h` の `USE_NEW_` で始まる3つが `0` になっていることを確認します。
3. いつもと同じ手順で書き込みます。`mcr_gpt_lib.h` は今まで通りライブラリとして入っている必要があります。
4. 前のプログラムで走らせたことのあるコースを、DIPスイッチも同じ設定にして3回走らせます。
5. microSD のログ（`logNNNN.csv`）を前のプログラムのログと比べます。列の並びは前と同じです（`ms,pattern,sensor,handle,motor_l,motor_r`）。
   - 同じ場所で同じ pattern 番号に変わっていれば問題ありません。
   - 走るたびに細かい違いは出ます（センサの読み取りやバッテリーの電圧が毎回少し違うため）。

ここで動きが明らかに違う場合は、新しいアルゴリズムに進まずに連絡してください。

## 2. 新しいアルゴリズムの考え方

Basicマイコンカーには、速さを直接測るセンサ（エンコーダ）がありません。そこで次の2つの方法で速さを求めています（`speed_model.ino`）。

1. **モータの出力から計算する**：出力 p[%] を出し続けると、速さは `p/100 × V_MAX_MPS` に近づいていきます。近づく速さは時定数 `MOTOR_TAU_S` で決まります（一次遅れのモデル）。これを 1ms ごとに計算します。
2. **ラインの通過時間で測り直す**：クロスラインとハーフラインは幅が決まっています。通過にかかった時間から `速さ = 幅 ÷ 時間` で実際の速さが分かるので、1 の計算値をこの値に置き換えます。

### 2-1. クランク（`USE_NEW_CRANK_BRAKE`）

- **元の方法**：クロスラインの通過時間ごとに「全開の時間」「ブレーキの強さ」を決めた表（25段階）を使っていました。
- **新しい方法**：クロスラインを通過し終わった地点からの距離を計算し続けます。1ms ごとに「今ブレーキをかけたら、`CRANK_ENTRY_MPS` まで落ちるのに何 m 必要か」を計算します。その距離が残りの距離（`CROSS_TO_CRANK_M − 走った距離 − CRANK_BRAKE_MARGIN_M`）に達するまでは全開で走ります。達したらブレーキをかけ、目標の速さまで落ちたらその速さを保ちます。
- **この方法を選んだ理由**：加速と減速の強さに上限がある場合、決まった距離で目標の速さまで落とすのに一番時間がかからないのは、「全開 → ぎりぎりで最大ブレーキ → 目標の速さを保つ」という切り替え方です。最適制御の分野でバン・バン制御と呼ばれる方法です。表で決める方法と違って、速さが変わっても自動でブレーキの開始地点がずれます。
- クランクを見つけた後（pattern 110 以降）の曲がり方は、元の表のままです。

### 2-2. レーンチェンジ（`USE_NEW_LANE_BRAKE`）

- クランクと同じ考え方で、ハーフラインの終わりから `HALF_TO_LANE_M` 先で `LANE_ENTRY_MPS` になるように減速します。
- 中央線が切れたらハンドルを切る、という流れは元のままです。ハンドルを切る時間とモータの値は、元の段階（ハーフラインの通過時間で決まる 0〜10）の表を使います。

### 2-3. 通常走行のカーブ（`USE_NEW_TRACE_SPEED`）

- **元の方法**：直線が続いた時間で段階 0〜5 を決め、段階ごと・センサ値ごとに内輪のモータ値を表で決めていました（6 × 13 の表）。
- **新しい方法**：ハンドル角度 θ から、曲がりの半径 R を `R = WHEELBASE_M ÷ tan(θ)` で計算します。そこから次の2つを決めます。
  - 外輪の出力：横すべりしないで曲がれる速さの上限 `v = √(LATERAL_ACCEL × R)` を出力[%]に直した値
  - 内輪の出力：外輪 × `(R − TREAD_M/2) ÷ (R + TREAD_M/2)`。内輪と外輪が実際に回る距離の比です。
- **この方法を選んだ理由**：表の数値（13 × 6 = 78個）ではなく、測れる値3つ（ホイールベース、トレッド、横方向の加速度）で決まります。そのため調整が速く済みます。参考までに、元の段階0の表の内輪の値は、ホイールベース170mm・トレッド150mmで計算した比とほぼ一致しています（例：18度で計算 75%、表 75%）。
- ハンドル角度は元の表のまま使います。大曲がり（pattern 30〜45）の処理も元のままです。

### 2-4. 対応していないもの

- **坂**：Basicマイコンカーには坂を検出するセンサ（傾きセンサやエンコーダ）がありません。そのため、坂専用の処理は入れていません。上り坂で遅くなると、速度の推定（計算値）が実際より速くなります。ただし次のクロスライン・ハーフラインで測り直すので、ずれはそこで直ります。

## 3. 新しいアルゴリズムを使う前に測る値

ログに速さの推定値を出すため、`config.h` の `LOG_SPEED_MODEL` を `1` にしておきます。ログの最後に `speed_mm_s`（推定した速さ[mm/s]）と `dist_mm`（ラインの終わりからの距離[mm]）の2列が増えます。調整が終わったら `0` に戻してかまいません。

### 3-1. 車体の寸法（定規で測る）

| 設定 | 測る所 | 単位 |
|---|---|---|
| `WHEELBASE_M` | 前輪の軸の中心から後輪の軸の中心まで | m（170mm なら `0.170f`） |
| `TREAD_M` | 左右の後輪の、タイヤの幅の中心どうしの距離 | m |

### 3-2. ラインの幅（コースで測る）

| 設定 | 測る所 |
|---|---|
| `CROSS_LINE_WIDTH_M` | センサが「クロスライン」と判定している間に進む距離。クロスラインの白い部分の、進行方向の長さ |
| `HALF_LINE_WIDTH_M` | 同じくハーフラインの白い部分の、進行方向の長さ |
| `CROSS_TO_CRANK_M` | クロスラインの終わり（車から見て奥側の端）から、クランクの曲がり角の白線まで |
| `HALF_TO_LANE_M` | ハーフラインの終わりから、中央線が切れている所まで |

大会のコースでは距離が変わることがあります。大会のルールに書かれている範囲の**一番短い値**を入れておくと安全です。

### 3-3. 最高速度 `V_MAX_MPS`（出力100%での速さ）

1. DIPスイッチを 3（100%）にします。
2. 長い直線（2m以上）の途中に、間隔を測ったクロスラインを2本置きます。例えば 1.5m 間隔にします。クロスラインがなければ、白いテープを横に貼っても構いません。
3. 1本目までに十分加速できる位置からスタートさせます。
4. ログの `sensor` 列で、クロスラインの形（`'111xx111` のような行）が現れた時刻 `ms` を2本分読み取ります。
5. `V_MAX_MPS = 間隔[m] ÷ (2本目の時刻 − 1本目の時刻)[s]`
   - 例：1.5m を 0.52秒 → 2.88 m/s
   - ログは10msごとなので、間隔が長いほど誤差が小さくなります。

### 3-4. 時定数 `MOTOR_TAU_S`

1. 3-3 と同じ直線で、スタートから全開で走らせます。
2. スタートから 0.3m、0.6m、0.9m … の位置に白いテープを貼り、ログで通過時刻を読みます。
3. 区間ごとの速さを計算し、`V_MAX_MPS × 0.63` に達した時刻を読みます。その時刻（秒）が `MOTOR_TAU_S` です。
4. 簡単に済ませる方法もあります。`LOG_SPEED_MODEL = 1` で走らせ、クロスラインを通過した直後の `speed_mm_s` の変化を見ます。クロスラインで測り直した瞬間に推定値が大きく跳ねる場合は、`MOTOR_TAU_S` か `V_MAX_MPS` が合っていません。
   - 測り直した値の方が**小さく**跳ねる → 推定が速すぎる。`V_MAX_MPS` を下げるか `MOTOR_TAU_S` を大きくする
   - 測り直した値の方が**大きく**跳ねる → 推定が遅すぎる。逆に直す

## 4. 新しいアルゴリズムを1つずつ有効にする

必ず1つずつ `1` にして、それぞれ確かめてから次に進みます。2つ以上を同時に変えると、うまくいかなかったときに原因が分からなくなります。

### 4-1. クランク（`USE_NEW_CRANK_BRAKE = 1`）

最初は安全な値から始めます。

| 設定 | 最初の値 | 意味 |
|---|---|---|
| `CRANK_ENTRY_MPS` | `1.0f` | クランクに入る速さ。元のプログラムで曲がれていた速さより低めから始める |
| `CRANK_BRAKE_POWER` | `-60` | ブレーキの強さ（-100 が最大） |
| `CRANK_BRAKE_MARGIN_M` | `0.15f` | 早めにブレーキをかける余裕 |

手順:
1. クランクのあるコースを5回走らせ、5回ともクランクを抜けられるか確かめます。
2. ログで pattern 102・103 の行を見ます。`motor_l` / `motor_r` が「100 → マイナス（ブレーキ）→ 一定の値」の順に変わっていれば、計算どおりに動いています。
3. `dist_mm` 列で、pattern 110（クランク突入）になった時の距離を見ます。
   - `CROSS_TO_CRANK_M` より大きく手前（例えば 0.1m 以上手前）で目標の速さに落ち切っている → `CRANK_BRAKE_MARGIN_M` を 0.02m ずつ減らす
   - クランクで外にはみ出す（pattern 121 / 161 が出る）→ `CRANK_ENTRY_MPS` を 0.1 下げる、または `CRANK_BRAKE_MARGIN_M` を増やす
4. 5回とも抜けられたら、`CRANK_ENTRY_MPS` を 0.1 ずつ上げます。失敗したら 0.2 戻します。
5. ブレーキの区間でタイヤが滑って向きが乱れる場合は、`CRANK_BRAKE_POWER` を -60 → -40 のように弱めます。

### 4-2. レーンチェンジ（`USE_NEW_LANE_BRAKE = 1`）

4-1 と同じ手順で、`LANE_ENTRY_MPS` / `LANE_BRAKE_POWER` / `LANE_BRAKE_MARGIN_M` を調整します。
失敗の見分け方:
- pattern 440〜450 / 740〜750（新しい車線で外へふくらんだ）がよく出る → `LANE_ENTRY_MPS` を下げる
- pattern 340〜350 / 640〜650（ハンドルを切り終わっても新しい線が見えない）が長く続く → 車線変更の角度が足りません。`LANE_STEER_ANGLE` を 1〜2 度ずつ増やす

### 4-3. 通常走行（`USE_NEW_TRACE_SPEED = 1`）

1. `LATERAL_ACCEL` を `5.0f` から始めます。
2. 周回コースを5回走らせ、コースアウトしないことを確かめます。
3. `LATERAL_ACCEL` を 1.0 ずつ上げます。カーブで外にふくらむ（pattern 30〜45 が増える、またはコースアウトする）ようになったら、1つ前の値に戻します。
4. 直線でハンドルが小刻みに揺れて遅くなる場合は、`TRACE_MIN_POWER` を上げます。

## 5. 元の表（tables.h）を直接調整する場合

新しいアルゴリズムを使わない部分は、`tables.h` の表で調整します。

- `AM(角度, 左モータ, 右モータ)` の数値を変えます。表の1行が1つの段階です。
- 例：通常走行の段階3で、センサが `0x07`（右寄りの中程度のカーブ）のときに内輪をもっと減速したい場合
  1. `TRACE_SENSOR` で `0x07` が何番目かを見る → 6番目（0から数えて5）
  2. `TRACE_ACT` の `// pattern 23` の行の6番目 `AM( 19, 100,  57)` の右モータ `57` を変える
- 段階が上がる条件（直線が続く時間）は `config.h` の `TRACE_STAGE_UP_MS` です。

よくある症状と直す場所:

| 症状 | 直す場所 |
|---|---|
| 直線でハンドルが左右に揺れる | `TRACE_ACT` の 0x1c / 0x38 の角度（今は ±2）を小さくする |
| カーブで外にふくらむ | `TRACE_ACT` の内輪の値を下げる。または `TRACE_STAGE_UP_MS` を大きくして、速い段階に上がりにくくする |
| クランクで外にはみ出す | `CRANK_RAMP`（元の方法）か `CRANK_ENTRY_MPS`（新しい方法）で進入速度を下げる |
| サーボの中心がずれている | `SERVO_CENTER` を 10 ずつ変える |

## 6. 書き換えた後に PC で確かめる方法（任意）

`tools/host_test/compare.sh` を使うと、元のプログラムと動きが同じかどうかを PC で確かめられます（`g++` が必要です）。
新しいアルゴリズムのスイッチや表の数値を変えた場合は、元と動きが変わるので「不一致」と出るのが正しい結果です。
リファクタリングのように「動きを変えずに書き方だけ直した」ときの確認に使ってください。詳しくは `tools/host_test/README.md` にあります。
